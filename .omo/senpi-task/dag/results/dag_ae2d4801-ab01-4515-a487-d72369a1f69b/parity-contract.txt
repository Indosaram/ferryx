# Ferryx Worktree-to-Tab Behavior & UX Contract Recovery Report

---

## 1. Executive Summary & Recovered Behavior

Ferryx models an AI developer workspace containing multiple Git worktrees under a registered project. Every terminal execution and embedded browser companion belongs to a workspace project and is associated with a specific worktree context (CWD, branch identity, and lifecycle).

When switching worktrees:
1. **Selection & Activation**: Selecting a worktree in the sidebar must switch `activeWorktreePath`. If a terminal tab already exists for that worktree, it is focused/activated; if none exists, a new terminal tab is automatically spawned in that worktree's directory.
2. **Reverse Routing**: Activating a tab (via TabBar, shortcut `⌘1..9`, or Command Palette `⌘K`) whose session belongs to a different worktree updates the active worktree in the UI to match that tab's owning worktree.
3. **Resource Lifecycle & Cleanup**: When a worktree is deleted or pruned, all associated resources (PTY sessions, xterm instances, and child webviews) are cleanly terminated and removed from the layout.

## 3. Observable UX Contract

Any implementation or fix must satisfy the following verifiable contracts:

### A. Worktree Navigation & Tab Routing
1. **Sidebar Worktree Click**:
   - Given worktree $W_A$ is active: clicking worktree $W_B$ in the sidebar sets $W_B$ as active (`activeWorktreePath = W_B.path`).
   - If a terminal tab already exists with `worktreePath === W_B.path`, that tab becomes active.
   - If no terminal tab exists for $W_B$, a new terminal tab is created with CWD set to $W_B.path$ and auto-focused.
2. **TabBar Tab Click / Cycle (`⌘1..9`, `⌃PageUp/Down`)**:
   - Activating a tab belonging to worktree $W_B$ must immediately update the active sidebar worktree selection to $W_B$.
3. **New Tab Creation (`⌘T`, `+`)**:
   - Triggering a new terminal tab creates it attached to the currently active worktree (`state.activeWorktreePath`), inheriting its branch name label and working directory.

### B. Embedded Browser Ownership
1. **Browser Tab Association**:
   - Creating a browser tab (via `⌘⇧B`, `NewTabPopover`, or dev server port click) tags the browser runtime with the current `workspaceId` and `worktreePath`.
2. **Isolation & Safety**:
   - Closing a browser tab destroys its native child webview (`cmd_browser_close`) without killing any terminal PTY.
   - Deleting a worktree tears down all terminal sessions and child webviews bound to that worktree.

### C. Session Persistence & Restart Recovery
1. **Restart Tab Preservation**:
   - Quitting Ferryx and relaunching must restore all open tabs (terminal and browser), split pane hierarchies, pane ratios, and worktree associations.
2. **PTY Reattachment & Respawn**:
   - If the background daemon preserved PTYs, tabs reattach to live sessions.
   - If PTYs were terminated (cold restart), dead sessions are detected against `listSessions()`, respawned in their original worktree CWD, and bound without mutating local session IDs or dropping pane split layouts.

## 4. Remaining Ambiguity & Gaps

1. **Unified TabBar vs. Per-Worktree Tab Filtering**:
   - *Original Orca*: Strictly scoped `tabsByWorktree` (switching worktrees completely swapped the TabBar contents).
   - *Ferryx Documented Architecture*: Uses a global `layout.tabs: WorkspaceTab[]` list containing tabs from all worktrees within the project, with unread indicators mapped per worktree (`workspaceStore.ts:654-663`, `BROWSER_SUPPORT_PLAN.md:§9.4`).
   - *Ambiguity*: Should non-active worktree tabs remain visible in the top TabBar at all times (current design), or should the TabBar filter to show only tabs of the active worktree? Current tests and store design affirm the **unified TabBar** with cross-worktree tab switching.
2. **BrowserTab State Schema Gap**:
   - `BROWSER_SUPPORT_PLAN.md:§9.1` specifies `worktreePath` in `BrowserTab`, but `ui/src/state/workspaceStore.ts:484-495` does not persist `worktreePath` on the frontend `BrowserTab` object, causing `getTabWorktreePath` and `SET_WORKTREES` pruning to treat browser tabs as worktree-agnostic.
