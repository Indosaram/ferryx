### Ferryx Worktree / Tab / Session Persistence Audit Report

#### 1. Current Storage Key and Serialization/Restore Flow
- **Storage Keys**:
  - Registered projects metadata is persisted in `localStorage` under `PROJECTS_STORAGE_KEY` (`"ferryx.projects"`, with fallback migration for legacy keys in `ui/src/lib/storageKeys.ts:1-21`).
  - Active project selection is persisted in `localStorage` under `ACTIVE_PROJECT_STORAGE_KEY` (`"ferryx.active-project"` in `ui/src/lib/storageKeys.ts:2`).
  - Tab layouts, pane trees, and terminal session states are **not** persisted in `localStorage`. They are saved to and loaded from native disk via Tauri IPC commands `cmd_session_save` and `cmd_session_load` (`saveSession` / `loadSession` in `ui/src/lib/tauri.ts:420-428`).
- **Serialization Flow**:
  - Invoked during window close guard (`ui/src/App.tsx:238-242`) and via a 500ms debounced auto-save timer whenever tabs and worktrees exist (`ui/src/App.tsx:244-251`).
  - `serializeWorkspaceState(activeProject.workspaceId, activeProject.repoRoot, state)` (`ui/src/lib/sessionPersistence.ts:20-109`):
    - Normalizes layout state (`normalizeLayout(state.layout)`).
    - Serializes worktrees into `PersistedWorktree[]` and tabs into `PersistedTab[]` with their respective pane trees, active leaf IDs, and session-leaf mappings (`ui/src/lib/sessionPersistence.ts:26-65`).
    - Gathers all actively referenced terminal sessions into `persistedTerminalSessions` (`ui/src/lib/sessionPersistence.ts:80-96`).
    - Constructs a `PersistedWorkspaceSession` object containing version 2 and a single-entry dictionary `workspaces: { [workspaceId]: workspace }` (`ui/src/lib/sessionPersistence.ts:104-108`).
    - Dispatches to `saveSession(session)` (`ui/src/lib/tauri.ts:420-423`).
- **Restore Flow**:
  - Restores on initial mount and whenever `activeProject.workspaceId` transitions (`ui/src/App.tsx:145-236`).
  - `loadSession()` retrieves the persisted session payload via IPC (`ui/src/App.tsx:149`).
  - Live backend PTYs are queried via `defaultTauriTransport.listSessions()` (`ui/src/App.tsx:152`).
  - `deserializeWorkspaceState(activeProject.workspaceId, session, liveBackendIds)` (`ui/src/lib/sessionPersistence.ts:111-236`) parses `session.workspaces[workspaceId]`, reconstructs `Worktree[]`, `TerminalSession` map (matching live backend PTY IDs), and tab pane layouts.
  - Passes restored state to `restoreWorkspace(restoredState)` (`ui/src/App.tsx:156`) and triggers `spawnTerminal(...)` for any dead PTYs (`ui/src/App.tsx:159-180`).

#### 2. State Partitioning Scope (Project vs. Worktree vs. Shared Global)
- **Session Data Model**: Keyed by **project** at the top-level dictionary (`workspaces: Record<string, PersistedWorkspace>` in `ui/src/lib/types.ts:314-320` and `ui/src/lib/sessionPersistence.ts:104-108`). Inside each project workspace, all worktrees share a single global `layout` and tab collection (`layout: PersistedLayout`), while individual terminal sessions record their associated `worktreePath` (`ui/src/lib/sessionPersistence.ts:91`).
- **Runtime In-Memory State**: Managed by a single `useWorkspaceStore` hook instance at root `App` (`ui/src/App.tsx:87-117`). State is **shared globally in-memory across project switches** without being re-initialized or partitioned by project instance in `useReducer` (`ui/src/state/workspaceStore.ts:113-116, 692-701`).

#### 3. Exact Likely Fault Mechanism

1. **Restart Session Loss across Projects**:
   - `serializeWorkspaceState` constructs the session envelope with only the current project in `workspaces: { [workspaceId]: workspace }` (`ui/src/lib/sessionPersistence.ts:104-108`).
   - Every auto-save (`ui/src/App.tsx:244-251`) and close-guard save (`ui/src/App.tsx:238-242`) completely overwrites the global persisted session file with a single project's workspace, discarding all other registered projects.
   - When switching projects or restarting the application, `deserializeWorkspaceState` returns `null` for any non-last-saved project (`ui/src/lib/sessionPersistence.ts:115-116`), resulting in tab and session loss.

2. **Cross-Project / Cross-Worktree Tab & Session Leakage**:
   - When switching `activeProjectId` (`ui/src/App.tsx:265-274`), `useWorkspaceStore` retains the previous project's `state.layout.tabs` and `state.sessions` in memory because `useReducer` does not reset on prop changes.
   - Before `registerProject` and `refreshWorktrees` complete asynchronously, the 500ms debounced auto-save (`ui/src/App.tsx:244-251`) executes with `activeProject.workspaceId = "new-project"` and `state` containing the **old project's tabs**, serializing the previous project's tabs into the new project's session payload.
   - In `workspaceReducer` under `SET_WORKTREES` (`ui/src/state/workspaceStore.ts:707-737`), non-terminal browser tabs (`tab.kind === "browser"`) are explicitly excluded from session-worktree validation (`ui/src/state/workspaceStore.ts:717`), causing browser tabs to leak unconditionally across project and worktree transitions.
