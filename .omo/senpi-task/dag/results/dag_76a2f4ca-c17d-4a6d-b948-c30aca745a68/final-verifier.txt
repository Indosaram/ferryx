## 종합 판정 (Korean)

orca-lite의 **백엔드와 계약 계층은 설계 계획에 부합**합니다. 4개 게이트가 모두 exit 0이고(제가 직접 재실행한 `bun run --cwd ui test`도 exit 0 / 26 tests), 이전 5건의 검증 실패는 현재 트리에서 전부 해소되었습니다. PTY 생명주기, 1-Writer-1-Worktree lease, dirty/unmerged 삭제 방어, Git 인자 하드닝, CSP, camelCase + 구조화 에러, 지연 로딩 번들 분리까지 Phase 1~5 및 Phase 8의 핵심 불변식은 코드와 테스트 양쪽에서 실증됩니다. 그러나 **UI/UX 축의 파리티는 미달**입니다. 브라우저·에디터·PR·원격 호스트·자동화·에이전트 오케스트레이션의 부재는 by-design gap이므로 결함이 아니지만, 그 예외를 걷어내고 남는 영역—키보드 단축키(원본은 terminal/tab 계열 30여 개 바인딩, lite는 TabBar 닫기 하나), 설정 화면(터미널/외관/단축키 섹션은 gap 예외 대상이 아님에도 전무하며 사이드바에 동작하지 않는 Settings 버튼만 노출), 사이드바·분할 리사이즈, 그리고 정의되지 않은 semantic Tailwind 토큰—은 모두 실제 결함입니다. 가장 심각한 것은 계층 간 모순입니다: 백엔드가 워크트리당 writer를 하나로 강제하는데 프론트엔드는 같은 워크트리에서 분할 시 두 번째 세션을 띄우고, 마지막 탭을 닫을 때도 기존 세션을 해제하기 전에 교체 세션을 먼저 띄웁니다. 이는 릴리스 체크리스트의 "single-tab split이 정상 작동합니다"와 "마지막 tab close 이후 valid state가 유지됩니다" 두 항목을 런타임에서 무력화할 가능성이 크며, 현재 프론트 테스트는 lease 의미론이 없는 가짜 spawn을 쓰기 때문에 이 결함을 잡아내지 못합니다. 또한 `worktree_changed`가 dirty/lock/prune/branch-change 종류를 발행하지 않는 점은 Phase 6.1로부터의 계획 이탈이고, macOS 네이티브 런타임 스모크·10회 반복 누수·프롬프트 유실 항목은 어떤 아티팩트로도 증명되지 않아 **unverified**로 남습니다. 결론적으로 **릴리스 승인 불가**이며, 특히 lease 모순 1건은 기능 차단성 결함으로 우선 처리해야 합니다.
