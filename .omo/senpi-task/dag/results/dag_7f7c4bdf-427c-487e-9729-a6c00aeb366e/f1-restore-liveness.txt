> I read this as fixing audit defect F1 where restored terminal tabs attach to dead PTY sessions on app restart - inspect current codebase, add failing tests (RED), implement liveness check / respawn fix, verify tests pass (GREEN), typecheck clean.

### Summary of Changes

1. **Session Persistence Liveness Support (`ui/src/lib/sessionPersistence.ts`)**:
   - Updated `deserializeWorkspaceState` to accept an optional `liveBackendSessionIds` parameter (`Iterable<string> | null`).
   - When `liveBackendSessionIds` is provided, any restored session whose `backendSessionId` is not in the live set receives `backendSessionId: null`, signaling that its backend PTY is dead.

2. **Transport Wiring & Respawn on Restore (`ui/src/App.tsx`)**:
   - Wired `defaultTauriTransport.listSessions()` from `ui/src/lib/terminalTransport/tauriTransport.ts` into the startup restore flow.
   - Restores workspace tabs immediately with dead sessions marked as `backendSessionId: null`.
   - Iterates through dead sessions (`!sess.backendSessionId`) and respawns them via `spawnTerminal({ workspaceId, worktree })`, updates `backendSessionId` to the newly spawned session, and updates the workspace store. Live sessions during dev/HMR are preserved without redundant respawns.

3. **Transport & Component Tests (`ui/src/lib/sessionPersistence.test.ts`, `ui/src/lib/terminalTransport/terminalTransport.test.ts`, `ui/src/App.test.tsx`)**:
   - Added unit test asserting `deserializeWorkspaceState` nulls `backendSessionId` when not present in live backend sessions.
   - Added unit test asserting `TauriTerminalTransport.listSessions()` queries `listTerminalSessions()` and maps the session summaries.
   - Added integration tests for `App.tsx` verifying:
     - Dead terminal sessions are respawned on app restart.
     - Live backend sessions are preserved without respawning on dev/HMR.
     - Split pane layouts with mixed live and dead sessions respawn only the dead sessions.
