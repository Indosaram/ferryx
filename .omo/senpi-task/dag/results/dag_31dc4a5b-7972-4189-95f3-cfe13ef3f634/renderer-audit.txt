### 1. Verification & Current Lifecycle Findings

#### A. Does an xterm instance survive inactive tab/workspace transitions?
**Yes.**
- When a tab becomes inactive or a workspace switch occurs, `TerminalPane` unmounts from the React tree (`ui/src/components/TerminalPane.tsx:30-64`). Its cleanup function only sets `cancelled = true` (`TerminalPane.tsx:61-63`) without invoking `terminalHostManager.destroy(sessionId)`.
- `terminalHostManager` retains the full `TerminalInstance` (`ui/src/lib/terminalHostManager.ts:28-65`) in its private `instances = new Map<string, TerminalInstance>()`.
- The detached `TerminalInstance` keeps its `Terminal`, `FitAddon`, `SearchAddon`, WebGL context (`disposeWebgl`), `ResizeObserver`, and PTY output subscription (`unsubscribeOutput`) fully alive and resident in memory.
- When switching back, `TerminalPane` calls `terminalHostManager.getOrCreate()` (`TerminalPane.tsx:35-37`), hitting the cached instance (`terminalHostManager.ts:42-49`) and reattaching `instance.element` via `container.replaceChildren(instance.element)` (`TerminalPane.tsx:40`).

#### B. Where subscriptions and resources are released
- **PTY Output Subscription (`unsubscribeOutput`)**:
  - Re-subscribed/released on backend ID change: `TerminalHostManager.updateSession()` (`ui/src/lib/terminalHostManager.ts:213`).
  - Released on explicit session destroy: `TerminalHostManager.destroy()` (`ui/src/lib/terminalHostManager.ts:240`).
- **Terminal UI / DOM Disposables (`onData`, `onTitleChange`, `onBell`, `pointerdown`)**:
  - Released on explicit session destroy: `TerminalHostManager.destroy()` (`ui/src/lib/terminalHostManager.ts:241`).
- **WebGL Addon Renderer**:
  - Context loss disposal: `addon.onContextLoss()` in `attachWebglRenderer()` (`ui/src/lib/terminalRenderer.ts:58-61`).
  - Explicit session destroy: `TerminalHostManager.destroy()` calls `inst.disposeWebgl()` (`ui/src/lib/terminalHostManager.ts:243`).
- **Search Addon, ResizeObserver, xterm Core, DOM Element**:
  - Released only on explicit session destroy in `TerminalHostManager.destroy()` (`ui/src/lib/terminalHostManager.ts:239-245`).
- **Caller of `TerminalHostManager.destroy()`**:
  - Only `workspaceStore.ts` invokes `destroy()` on explicit user actions: closing a tab (`ui/src/state/workspaceStore.ts:421, 432`), closing a pane (`ui/src/state/workspaceStore.ts:454`), or pruning removed worktree sessions (`ui/src/state/workspaceStore.ts:509`).

### 3. Minimal Proposed Data Model (Visible + LRU Warm-Cache)

To prevent WebGL context exhaustion (>8–16 contexts) and unbounded memory growth from background tabs while keeping active split panes and recently switched tabs instantly responsive:

```ts
// ui/src/lib/terminalHostManager.ts
type WarmCacheConfig = {
  maxInactiveWarmInstances: number; // e.g., 4
};

class TerminalHostManager {
  private instances = new Map<string, TerminalInstance>();
  private pendingSpawns = new Map<string, Promise<TerminalInstance>>();
  
  // Set of session IDs currently mounted in visible TerminalPane components (including splits)
  private visibleSessionIds = new Set<string>();
  
  // LRU access order for inactive instances (oldest at front, MRU at back)
  private inactiveLruKeys: string[] = [];

  markVisible(sessionId: string): void;
  markInactive(sessionId: string): void;
  private pruneInactiveWarmCache(): void;
}
```

#### Ownership Transitions in the Seam:
1. **Mount (`TerminalPane` -> `markVisible(sessionId)`)**:
   - `visibleSessionIds.add(sessionId)` (pinned from eviction).
   - Removed from `inactiveLruKeys` if present.
   - If evicted earlier or renderer detached, rehydrates via `getOrCreate(session)` (with `terminalEventBus` backlog replay).
2. **Unmount (`TerminalPane` cleanup -> `markInactive(sessionId)`)**:
   - `visibleSessionIds.delete(sessionId)`.
   - Appends `sessionId` to `inactiveLruKeys`.
   - Triggers `pruneInactiveWarmCache()`: while `inactiveLruKeys.length > maxInactiveWarmInstances`, shifts oldest inactive key and invokes `this.destroy(evictedSessionId)` (or detaches WebGL context down to Canvas/headless).
3. **Explicit Close (`workspaceStore` -> `destroy(sessionId)`)**:
   - Cleans up `visibleSessionIds`, `inactiveLruKeys`, and `instances`.

### 4. Critical Hazards & Failure Modes

1. **WebGL Context Limit & Context Loss (`terminalRenderer.ts:58-61`)**:
   - Browsers have hard limits (8–16 WebGL contexts). Without bounding inactive tabs, opening background tabs forces context loss, triggering fallback counters (`recordWebglContextLoss`).
2. **Split-Pane Eviction Risk (`TerminalSplitView.tsx:30-70`)**:
   - If the cache policy only tracks the single "active tab" instead of all visible pane sessions in split views, visible split panes could be prematurely evicted. Pinned `visibleSessionIds` tracking in `TerminalPane` mount lifecycle is essential.
3. **PTY Backlog Replay Bound (`terminalEvents.ts:5, 87-106`)**:
   - When an evicted instance is recreated upon re-activation, it relies on `terminalEventBus.subscribeOutput(..., replay = true)`. Replay is capped at `MAX_BACKLOG_CHARS = 512 * 1024` (`terminalEvents.ts:5`). Sessions with >512KB output will only preserve the tail 512KB.
4. **Async Spawn Race (`terminalHostManager.ts:52-64`)**:
   - If an inactive tab is evicted while its initial `createInstance` promise is still in `pendingSpawns`, eviction must cancel or abort the pending spawn promise to prevent orphaned instances re-entering `instances` after eviction.
5. **Zero-Dimension Resize on Reattach (`TerminalPane.tsx:47-51`, `terminalHostManager.ts:139-143`)**:
   - Reattaching an instance element before layout computation can trigger zero-dimension `fitAddon.fit()` calls. Must maintain `clientWidth > 0 && clientHeight > 0` guards.
