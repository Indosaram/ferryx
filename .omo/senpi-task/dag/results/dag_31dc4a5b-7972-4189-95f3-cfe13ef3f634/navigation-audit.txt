# Audit Report: Ferryx Known-Workspace and Tab Navigation

## 1. Executive Verification

**Can selecting a known parked workspace or tab return without terminal spawn, network call, or PTY wait?**
**YES.** When navigating to a known parked workspace that already has retained tabs (`parkedLayout.tabs.length > 0`), navigation is resolved entirely in memory via pure synchronous reducer state transitions (`SELECT_WORKTREE` and `ACTIVATE_TAB`). No `spawnTerminal`, no IPC network/filesystem call, and no `waitForTerminalExit` is triggered.

## 4. Parked-Layout Behavior (5 Workspaces × 20+ Live Terminals)

- **Layout Persistence (`worktreeLayouts`)**:
  - `ui/src/state/workspaceStore.ts:860-864`
  - Inactive workspaces store their entire `LayoutState` (`tabs`, `layoutsByTabId` binary split trees, pane ratios, tab groups, `activeLeafId`) in `state.worktreeLayouts[worktreePath]`.
- **PTY Process & Session Retention**:
  - `ui/src/state/workspaceStore.ts:848-874`
  - All 100+ sessions remain in `state.sessions`. No PTY is killed, suspended, or disconnected when parked. Background output buffers in `terminalEventBus` chunk rings and OSC title listeners continue processing in the background (`ui/src/lib/terminalEvents.ts`).
- **DOM / Canvas Virtualization**:
  - `ui/src/components/TerminalSplitView.tsx:145-165`, `ui/src/components/TerminalPane.tsx`
  - Only the active worktree’s currently active tab pane tree is mounted into the DOM / XTerm instances. Inactive tabs and all parked workspace terminals are kept out of React DOM, preventing 100+ concurrent WebGL/Canvas surfaces.
- **Background Activity Aggregation**:
  - `ui/src/state/workspaceStore.ts:619-674`
  - `selectWorktreeActivitySummaries` and `selectTabActivitySummaries` traverse `getAllTabs(state)` to surface badge indicators in `Sidebar.tsx` and `TabBar.tsx` for parked workspaces without activating them.

## 5. Minimal State-Only Fast-Path & Switcher Implications

### Minimal State-Only Fast-Path
- `ensureTabForWorktree` in `ui/src/state/workspaceStore.ts:208-251` is currently typed as `async (worktree: Worktree) => Promise<string>`. For known parked workspaces, the branch at lines `222-234` immediately dispatches `SELECT_WORKTREE` and `ACTIVATE_TAB`.
- **Fast-path optimization**: Expose a synchronous selector `hasKnownWorktreeLayout(state, path)` and a synchronous action dispatcher `selectKnownWorktree(path)` to bypass async promise microtask scheduling and IPC error-boundary wrapping (`reportRuntimeError`).
- In `ui/src/App.tsx:230-249` (`handleSelectTerminalTab`), the function only inspects `currentState.layout.tabs`. For parked tabs, dispatching `activateTab(tabId)` directly triggers the built-in parked-layout switch in `workspaceStore.ts:1067-1088` without requiring `ensureTabForWorktree`.

### Navigation Virtualization & Switcher Implications (100+ Terminals)
1. **`CommandPalette.tsx` (`ui/src/components/CommandPalette.tsx:16, 26, 60-103`)**:
   - `App.tsx:693` currently passes `tabs={state.layout.tabs}` (only active workspace tabs).
   - If updated to search all 100+ terminals across 5 workspaces via `getAllTabs(state)`, `CommandPalette`'s flat DOM list (`ui/src/components/CommandPalette.tsx:90-101`) will require list virtualization or top-N result truncation to avoid scroll lag during keystrokes.
2. **`TabBar.tsx` (`ui/src/components/TabBar.tsx:143-167`)**:
   - Renders all 20+ tabs of the active group in a horizontal `SortableContext`. 20+ tabs fit with overflow scroll, but drag-and-drop coordinate computation (`workspaceCollisionDetection`) scales linearly with tab count.
3. **Session State Serialization**:
   - `ui/src/App.tsx:164-173` debounces session persistence on `state` change. For 100+ sessions, `serializeWorkspaceState` handles full snapshot serialization; pruning parked terminal scrollback from disk serialization prevents IPC serialization stalls.
