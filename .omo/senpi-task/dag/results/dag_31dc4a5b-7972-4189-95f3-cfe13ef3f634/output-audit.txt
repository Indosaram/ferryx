# Audit Report: Ferryx Terminal Output Scheduling, Replay, and Activity Continuity

## 1. Executive Summary & Verification Findings
* **Immediate `terminal.write` Verification**: **YES**. Every incoming IPC chunk currently causes an immediate, synchronous `terminal.write(text)` call on the JS main thread (`ui/src/lib/terminalHostManager.ts:135`, `175`; `ui/src/remote/RemoteTerminal.tsx:137-139`). There is currently no animation-frame batching or write-queue scheduling on the frontend.
* **Inactive-Session Replay Verification**: Replay reaches inactive/reattached renderers via dual buffers:
  1. **Tauri Desktop**: The frontend singleton `TerminalEventBus` maintains an in-memory chunk ring (`SessionBacklog`) per session up to 512 KiB chars (`ui/src/lib/terminalEvents.ts:153-176`). When a renderer is mounted or switched, `subscribeOutput(..., replay = true)` synchronously replays the concatenated backlog into the newly bound `terminal.write` (`ui/src/lib/terminalEvents.ts:98-101`).
  2. **Remote / Daemon**: `TerminalService.attach()` fetches the Rust `BoundedBuffer` snapshot (up to 512 KiB) from `TerminalOutputHub` (`src-tauri/src/terminal/output_hub.rs:72-81`) and sends it as the initial binary frame over WebSocket (`src-tauri/src/remote/server.rs:479-481`).

## 5. Disjoint Output-Scheduling Write Scope & Minimal Batching Design

### Disjoint Scope Boundary
* **Do NOT batch inside `TerminalEventBus`**: `TerminalEventBus` must process raw IPC output immediately so OSC title extraction (`scanTerminalOscTitles`) and session backlog buffering remain real-time for inactive tabs, sidebar badges, and agent status indicators.
* **DO batch inside the Renderer Host Boundary**: Batching belongs strictly between `TerminalEventBus.subscribeOutput` and `xterm.write` inside `TerminalHostManager` (`ui/src/lib/terminalHostManager.ts`) or an instance wrapper (`TerminalOutputQueue`).

### Minimal Animation-Frame Batching Design
1. **Per-Instance Queue**: Each `TerminalInstance` maintains a `pendingChunks: string[]` and `writeRafId: number | null = null`.
2. **Coalesced RAF Flush**:
   ```ts
   const queueTerminalWrite = (inst: TerminalInstance, text: string) => {
     inst.pendingChunks.push(text);
     if (inst.writeRafId === null) {
       inst.writeRafId = requestAnimationFrame(() => {
         inst.writeRafId = null;
         if (inst.pendingChunks.length === 0) return;
         const batched = inst.pendingChunks.join("");
         inst.pendingChunks = [];
         inst.terminal.write(batched);
       });
     }
   };
   ```
3. **Synchronous Flush on Reattachment & Teardown**:
   - When a tab is switched or reattached (`replay = true`), the backlog must be prepended or written immediately before subsequent rAF chunks to avoid live-before-replay race conditions.
   - When `destroy(sessionId)` or `updateSession()` is called, cancel `inst.writeRafId` and drain `inst.pendingChunks` before `terminal.dispose()`.

---

## 6. Failure Hazards

1. **Replay vs. Live Interleaving**: If backlog replay is queued asynchronously alongside live incoming rAF batches, live output could render ahead of replay text, corrupting the xterm screen state.
2. **Activity / Spinner Starvation**: If rAF scheduling is placed upstream in `TerminalEventBus`, inactive/hidden tabs (where `requestAnimationFrame` is throttled by the browser to 1 fps or halted) would freeze tab title indicators and agent spinner updates.
3. **Disposed Instance Write Exception**: If an animation frame is pending when a tab is closed or split pane destroyed, calling `terminal.write()` inside the callback throws `TypeError: Terminal is disposed`.
4. **Renderer Main-Thread Starvation**: Synchronous large bursts without rAF coalescing lock the UI thread in xterm parser loops.
