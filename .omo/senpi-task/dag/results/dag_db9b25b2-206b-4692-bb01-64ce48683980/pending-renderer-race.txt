### Lifecycle Reasoning

1. **Generation Counter (`spawnGenerations: Map<string, number>`)**:
   - When `getOrCreate(session)` begins an asynchronous spawn, it increments and registers a monotonically increasing spawn generation number for that `session.id`.
   - When `destroy(sessionId)` is invoked, it immediately increments the generation for `sessionId`, in addition to clearing `visibleRefCounts`, removing from `inactiveLruSessionIds`, deleting `pendingSpawns`, and disposing any active instance.

2. **Resolution Invalidation & Resource Teardown (`disposeInstance`)**:
   - When `spawnPromise` resolves, `getOrCreate` compares the captured spawn generation with `this.spawnGenerations.get(session.id)`.
   - If the generation has advanced (invalidated by `destroy`), the newly resolved instance is immediately torn down using `disposeInstance(instance)`: disconnecting its `ResizeObserver`, disposing all registered event listeners, `SearchAddon`, WebGL addon, `Terminal`, removing the DOM element, and unlistening output subscriptions.
   - The invalidated instance is rejected from `this.instances` and skipped from `inactiveLruSessionIds` or LRU eviction bookkeeping.

3. **Safe Pending Spawn Cleanup**:
   - In the `finally` block of `getOrCreate`, deletion from `this.pendingSpawns` checks identity: `if (this.pendingSpawns.get(session.id) === spawnPromise) { this.pendingSpawns.delete(session.id); }`.
   - This ensures that if a subsequent `getOrCreate` for the same session was initiated while the old promise was resolving, the old promise's completion will not delete or disrupt the active pending promise of the new generation.

4. **Preserved Frontend Scope**:
   - No backend PTY close, spawn, or Tauri IPC calls are triggered by this lifecycle fix. Backend session records and PTY state remain isolated from frontend renderer lifecycle invalidations.
