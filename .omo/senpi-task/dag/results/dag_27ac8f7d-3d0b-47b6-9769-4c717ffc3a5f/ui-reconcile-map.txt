## 1. Identity Representation & Reconciliation Model

### 1.1 Three-Tier Identity Invariant
In accordance with `markdown/TERMINAL_SESSION_PERSISTENCE_FUNDAMENTAL_SOLUTION.md:88-109`, the UI maintains three distinct ID lifecycles:

| ID | Owner | Lifecycle | Representation in Code |
| :--- | :--- | :--- | :--- |
| `workspaceId` | Project Domain | Persistent / Configuration | `string` (`ui/src/lib/types.ts:25`, `App.tsx:96`) |
| `localSessionId` | React Layout / Leaf | Layout state lifetime | `session.id` (`ui/src/lib/types.ts:40`), referenced by `paneTree` leaf (`ui/src/lib/types.ts:107`) |
| `backendSessionId` | Native Daemon / PTY | Process lifetime | `session.backendSessionId` (`ui/src/lib/types.ts:46`), nullable (`string \| null`) |

### 1.2 Frontend Reconciliation Flow
```text
 persistedSession (v2) from loadSession()
                   │
                   ▼
  defaultTauriTransport.listSessions() ──► liveBackendIds: Set<string>
                   │
                   ▼
  deserializeWorkspaceState(workspaceId, session, liveBackendIds)
                   │
     ┌─────────────┴─────────────┐
     ▼                           ▼
[Backend ID in liveBackendIds]  [Backend ID missing / null]
  - keep localSessionId           - keep localSessionId & leaf tree intact
  - keep backendSessionId         - set backendSessionId = null
  - lifecycle: "working"          - lifecycle: "exited"
  - ATTACH existing session       - DO NOT auto-respawn
```

## 2. Component Analysis & File:Line Citations

### A. App Restore Effects (`ui/src/App.tsx`)
- **Current Lines `212-258` (`App.tsx`)**:
  - **StrictMode Failure**: `restoredProjectIdRef.current = activeProject.workspaceId` (`App.tsx:213-214`) is set synchronously on the first mount effect. In React StrictMode, effect cleanup aborts the first pass, and the second mount exits early (`App.tsx:213`), leaving the workspace unhydrated.
  - **Auto-Respawn Anti-Pattern**: Lines `234-257` (`App.tsx`) filter `deadSessions` and unconditionally execute `spawnTerminal(...)` for every session where `!candidate.backendSessionId`. Per `markdown/TERMINAL_SESSION_PERSISTENCE_FUNDAMENTAL_SOLUTION.md:104-108, 206-209`, sessions lost due to daemon crash or missing PTY must **not** be blindly auto-respawned into new shells; they must remain visible as `exited` leaves awaiting user action.
  - **Legacy Fallback Spawn Danger**: Lines `262-293` (`App.tsx`) execute `ensureTabForWorktree` when `hasRestoredTabs` is false, causing duplicate tabs and spurious spawns.
- **Required Implementation**:
  - Replace `restoredProjectIdRef` boolean lock with a formal restore coordinator state machine: `idle` | `loading` | `restored` | `failed`.
  - Effect cleanup must cancel in-flight queries (`cancelled = true`) without permanently setting `restored` if aborted before commit.
  - For live sessions (`backendSessionId !== null`), trigger `transport.attach(backendSessionId)`.

### B. HMR Registry (`ui/src/state/hmrWorkspaceState.ts`)
- **Current Lines `1-84` (`hmrWorkspaceState.ts`)**:
  - Global registry symbol: `__FERRYX_HMR_WORKSPACE_STATES__` (`hmrWorkspaceState.ts:7`).
  - HMR capture on every reducer dispatch: `ui/src/state/workspaceStore.ts:143` calls `setHmrWorkspaceState(workspaceId, nextState)`.
  - Store initialization: `ui/src/state/workspaceStore.ts:128-132` checks `getHmrWorkspaceState(workspaceId)`. When present, returns `{ state: hmrState, recoveredFromHmr: true }`.
  - `App.tsx:215` checks `if (recoveredFromHmr) return;` to avoid clobbering live memory from disk.
- **Required Implementation**:
  - Ensure HMR handoff retains the live `backendSessionId` mapping and does not trigger `closeTerminal` or `spawnTerminal` during Vite Fast Refresh.

### C. Workspace Store Session Types & Actions (`ui/src/state/workspaceStore.ts`)
- **Current Lines `28-38, 63-118, 440-448, 620-646` (`workspaceStore.ts`)**:
  - State holds `sessions: Record<string, TerminalSession>` (`workspaceStore.ts:31`).
  - Reducer actions currently include `RESTORE_WORKSPACE` (`workspaceStore.ts:440-448`) and `SESSION_LIFECYCLE` (`workspaceStore.ts:620-646`).
  - Disposal logic in `closeTab` (`workspaceStore.ts:309-354`) and `closePane` (`workspaceStore.ts:356-373`) extracts disposable sessions via `getDisposableSessionsForTab` (`workspaceStore.ts:1270-1282`) and calls `closeBackendSession` (`workspaceStore.ts:1302-1309`).
- **Required Implementation**:
  - Add explicit `ATTACH_BACKEND_SESSION` action: updates an existing `localSessionId` with a new or reconnected `backendSessionId` and marks `lifecycle: "working"` without altering pane tree geometry or leaf IDs.
  - Ensure `RESTORE_WORKSPACE` preserves intact leaf-to-session relationships for both live and dead sessions.

### D. Session Persistence Serialization (`ui/src/lib/sessionPersistence.ts`)
- **Current Lines `23-149, 151-297` (`sessionPersistence.ts`)**:
  - `serializeWorkspaceState` (`sessionPersistence.ts:120-128`) serializes `localSessionId: sess.id` and `backendSessionId: sess.backendSessionId`.
  - `deserializeWorkspaceState` (`sessionPersistence.ts:179-195`) already accepts `liveBackendSessionIds?: Iterable<string> | null`:
    ```ts
    const backendSessionId = liveSet
      ? (persistedBackendSessionId && liveSet.has(persistedBackendSessionId) ? persistedBackendSessionId : null)
      : persistedBackendSessionId;
    ```
- **Required Implementation**:
  - Maintain version `2` compatibility (`sessionPersistence.ts:21`).
  - Ensure missing backend sessions are deserialized with `backendSessionId: null` and `lifecycle: "exited"`.

### E. TerminalHostManager & Output Scheduler (`ui/src/lib/terminalHostManager.ts`, `terminalOutputScheduler.ts`)
- **Current Lines `71-82, 103-149` (`terminalHostManager.ts`) & `21-50` (`terminalOutputScheduler.ts`)**:
  - `markSessionVisible` (`terminalHostManager.ts:71-82`) calls `inst.terminal.reset()` and `attachScheduledOutputSubscription`.
  - `createTerminalInstance` (`terminalInstanceFactory.ts:170-173`) subscribes to `attachScheduledOutputSubscription` if visible.
  - `terminalOutputScheduler.ts:21-50` hooks into `terminalEventBus.subscribeOutput`.
- **Required Implementation**:
  - Ensure history replay from `transport.attach()` is written to `terminal.write()` **before** unblocking the live output scheduler queue.
  - Prevent duplicate scrollback on reconnect by clearing/resetting terminal buffer only when starting a fresh replay sequence.

### F. Terminal Transport & Tauri Bridge (`ui/src/lib/terminalTransport/*`, `tauri.ts`)
- **Current Lines `1-17` (`terminalTransport/types.ts`) & `13-78` (`terminalTransport/tauriTransport.ts`)**:
  - `TerminalAttachment` type: currently `{ sessionId: string; initialHistory?: Uint8Array; }` (`types.ts:3-6`).
  - `TauriTerminalTransport.attach(sessionId)`: currently returns a dummy `{ sessionId }` (`tauriTransport.ts:22-24`).
- **Required Implementation**:
  - Extend `TerminalAttachment` to support sequence numbers:
    ```ts
    export type TerminalAttachment = {
      readonly attachmentId?: string;
      readonly sessionId: string;
      readonly initialHistory?: Uint8Array;
      readonly historyStartSequence?: bigint;
      readonly historyEndSequence?: bigint;
    };
    ```
  - In `TauriTerminalTransport.attach(sessionId)`, invoke native `cmd_terminal_attach` (returning initial history buffer) and forward to the terminal host instance.

### Test 1: StrictMode Double-Mount Reconciliation
- **File**: `ui/src/state/workspaceStore.strictModeRestore.test.tsx`
- **Scenario**: Simulate React StrictMode double effect execution (mount -> cleanup -> mount).
- **Assertions**:
  - `loadSession()` is invoked.
  - `defaultTauriTransport.listSessions()` is invoked.
  - Exactly one `RESTORE_WORKSPACE` dispatch is executed.
  - Total `spawnTerminal` calls equal `0` when live backend sessions match persisted state.
  - Second mount does not get trapped in `idle` or `loading`.

### Test 2: Vite HMR Fast-Refresh Session Retention
- **File**: `ui/src/state/workspaceStore.hmrRetention.test.tsx`
- **Scenario**: Establish active workspace state with multiple split panes and parked layouts; trigger module reload where `recoveredFromHmr = true`.
- **Assertions**:
  - `storeServices.spawnTerminal` call count is strictly `0`.
  - `storeServices.closeTerminal` call count is strictly `0`.
  - All `TerminalSession.backendSessionId` values remain identical across the unmount/remount boundary.
  - Leaf IDs in `layoutsByTabId` retain their exact `sessionIdsByLeafId` bindings.

### Test 3: Missing / Lost Backend Session Behavior
- **File**: `ui/src/lib/sessionPersistence.restoreReconciliation.test.ts`
- **Scenario**: Pass persisted session with backend session `backend-dead-1` not returned by `listSessions()`.
- **Assertions**:
  - `deserializeWorkspaceState` outputs `sessions["local-1"].backendSessionId === null`.
  - `sessions["local-1"].lifecycle === "exited"`.
  - `layout.layoutsByTabId["tab-1"].sessionIdsByLeafId["leaf-1"] === "local-1"`.
  - No automatic PTY spawn is triggered without explicit user request.

### Test 4: History-Before-Live Output Invariant
- **File**: `ui/src/lib/terminalHostManager.attachHistoryOrder.test.ts`
- **Scenario**: Attach to an active session returning 4KB `initialHistory` while live output chunks concurrently arrive via event bus.
- **Assertions**:
  - `initialHistory` chunk is written to xterm at buffer index `0`.
  - Live output chunks with sequence numbers higher than history end sequence are appended after history without interleaving or dropped bytes.
  - No double replay occurs upon tab visibility toggle.
