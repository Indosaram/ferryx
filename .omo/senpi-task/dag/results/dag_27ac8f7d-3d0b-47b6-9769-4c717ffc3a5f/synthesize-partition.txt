## Bottom line

Six producer lanes are the smallest complete partition. File ownership is disjoint; after the Rust contract lane, daemon lifecycle, Tauri bridging, and UI transport can proceed with the handoff DTOs frozen. Overall effort: **Large**.

   - **Depends on:** none.
   - **Owns:**
     - `src-tauri/src/daemon/protocol.rs`
     - `src-tauri/src/terminal/mod.rs`
     - `src-tauri/src/terminal/output_hub.rs`

     - Monotonic per-session `u64` output sequences and bounded chunk history.

## Current design blockers

1. **The independent daemon cannot currently spawn registered project terminals.**  
   `src-tauri/src/daemon/server.rs:67-88` creates a private, empty `WorkspaceRegistry`, while `src-tauri/src/lib.rs:131-149` registers projects in a different GUI-owned registry. `src-tauri/src/daemon/protocol.rs:40-45` carries no repository root or registration command. Lane 1 must freeze `RegisterWorkspace`, and Lane 4 must invoke it before cutover.

2. **Attach currently monopolizes the same connection used for control.**  
   `src-tauri/src/daemon/server.rs:249-263` converts the connection into a permanent output pump, while `src-tauri/src/daemon/client.rs:61-64` has only one shared active connection. Multiple panes plus concurrent write/resize/close are impossible until Lane 2 creates dedicated attachment connections.

3. **Replacing only terminal IPC would still leave a GUI-owned terminal service through remote state.**  
   `src-tauri/src/lib.rs:131-140,172-175` creates and manages a direct `TerminalService`; `src-tauri/src/remote/state.rs:77-82` stores that concrete service; `src-tauri/src/remote/server.rs:560-607` attaches and writes through it. Lane 2 must make the daemon’s gateway authoritative, and Lane 4 must proxy remote commands before deleting the GUI service.
