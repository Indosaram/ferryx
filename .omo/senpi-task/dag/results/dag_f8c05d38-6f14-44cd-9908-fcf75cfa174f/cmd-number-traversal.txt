**What changed in `ui/src/App.tsx`**
- `listVisibleWorktrees(projects, worktrees, activeProjectId)` flattens the sidebar tree exactly as rendered: projects in registration order, each non-collapsed project followed by its own worktrees (ownership resolved from the `orca/<wsId>/<slug>` branch, falling back to the active project — same rule `Sidebar` uses to group).
- Collapse state is read from `SIDEBAR_COLLAPSED_PROJECTS_STORAGE_KEY` at key-press time, so it can never drift from the accordion the user sees. Defaults mirror the sidebar: persisted set wins; with nothing persisted, only the active project is expanded.
- `handleSelectWorktreeByIndex` indexes that flat list, so Cmd+N walks top to bottom straight across project boundaries. Out-of-range indexes hit `undefined` and do nothing.
- Cross-project targets now actually land: `handleSelectWorktree` switches the active project and parks the path in `pendingWorktreePath`; an effect ensures/focuses the tab as soon as that project's worktrees appear in the store, and a later explicit project switch discards a stale pending path.

**Tests**

I verified it fails when the handler is pointed back at `state.worktrees`.
- New out-of-range test: Cmd+5..9 with four visible worktrees touch nothing.
