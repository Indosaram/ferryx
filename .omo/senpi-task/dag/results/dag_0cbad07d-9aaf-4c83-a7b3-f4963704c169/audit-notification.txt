### Summary of Audit
- **Findings Identified**:
  - `F-notification-01` (Low): `load_terminal_preferences()` in `src-tauri/src/terminal/preferences.rs` invokes `ghostty +show-config` synchronously via `Command::new` on every query before checking local static config paths on disk.
  - `F-notification-02` (Low): macOS `UNUserNotificationCenter` settings query in `src-tauri/src/notification/permission.rs` uses synchronous blocking (`rx.recv_timeout(CALLBACK_TIMEOUT)`) across threads on every `service.dispatch()` without in-process status caching.
- **Accepted / Clean Patterns**:
  - Notification dispatch does not poll agent output or scan terminal PTY backlogs.
  - Audio decoding and file loading are offloaded to `tokio::task::spawn_blocking` (`run_blocking`), preventing reactor and UI thread blockage.
  - Audio deduplication short-circuits rapid repeated alerts within 400ms prior to disk I/O or decoder setup.
  - Audio player mutex locking occurs after decode and is dropped promptly after mixer player detachment.
