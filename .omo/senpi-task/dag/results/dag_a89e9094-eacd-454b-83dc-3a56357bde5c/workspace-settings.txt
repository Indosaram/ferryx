## 1) Data flow (source:line)

**Native registry (process memory, not disk)**

- `WorkspaceRegistry` is an in-memory `HashMap` created empty at app start (`src-tauri/src/worktree/registry.rs:8-15`, `src-tauri/src/lib.rs:119`).
- Startup registers at most the cwd Git root via `initial_project` (`lib.rs:126-134` → `ipc/project.rs:43-51`, `148-152`).
- Add/re-register goes through `cmd_project_register` → `register_canonical_project` (`project.rs:129-141`, `59-93`). Same canonical root returns the existing ID; it does not create a second alias.
- Exposed commands only: `cmd_project_initial`, `cmd_project_register`, `cmd_project_branches` (`lib.rs:168-170`). **There is no `cmd_project_list`.**

**Tauri bridge**

- `getInitialProject()` → `cmd_project_initial` (`ui/src/lib/tauri.ts:85-87`)
- `registerProject({ workspaceId, repoPath })` → `cmd_project_register` (`tauri.ts:81-83`)
- Return type is `{ workspaceId, repoRoot }` (`tauri.ts:21-24`)

**Frontend persistence (the durable project list)**

- Keys: `ferryx.projects` / `ferryx.active-project`, with `rorca.*` / `orca.*` migration (`ui/src/lib/storageKeys.ts:1-2`, `13-14`, `23-44`)
- `loadProjects()` / `persistProjects()` live only in App (`App.tsx:929-948`)
- Empty/invalid storage becomes `DEFAULT_PROJECT` `{ workspaceId: "default", repoRoot: "." }` (`App.tsx:52`, `929-940`)

**App bootstrap → live state**

1. Native: wait for `getInitialProject()`, then `canonicalizeProjectBootstrap(loadProjectBootstrap(), startup)` (`App.tsx:86-100`, `73-85`)
2. Non-native: load localStorage immediately (`App.tsx:89-91`)
3. Placeholder `{default, "."|""|startup.repoRoot}` is replaced by the native startup project and rewritten to localStorage (`App.tsx:66-85`)
4. `WorkspaceApp` holds `projects` / `activeProjectId` (`App.tsx:129-134`)
5. Active project is re-registered with native, then worktrees refresh. **Return value is discarded** (`App.tsx:217-224`)
6. Add Project writes native, then `handleRegisteredProject` updates React state + `ferryx.projects` (`ProjectDialogs.tsx:102-104`, `App.tsx:407-414`)
7. Sidebar **does** receive the live list (`App.tsx:762-771`)

**Settings Workspace**

- Dialog accepts optional `projects`, `activeProjectId`, `activeWorktree`, and action callbacks (`SettingsDialog.tsx:61-70`)
- Body defaults `projects = []`, `activeWorktree = null` (`SettingsDialog.tsx:97-104`)
- Workspace section renders that list; `projects.length === 0` → **"No projects registered."** (`SettingsDialog.tsx:189-197`, `570-625`, `669-671`)
- App mounts: `<SettingsDialog open onClose={handleCloseSettings} />` — **no project props** (`App.tsx:844-846`)
- Isolated Settings tests pass a fixture and pass (`SettingsDialog.workspace.test.tsx:35-76`). App tests mock Settings and drop extra props (`App.test.tsx:208-214`)

## 2) Why a real workspace looks absent

**Primary, sufficient cause:** App never forwards `projects`. Settings always sees `[]` and prints the empty copy, even while Sidebar shows the same workspace.

That matches the product bug exactly. A registered project in localStorage + native registry + sidebar is still invisible in Settings.

**Related display holes at the same mount (same missing props):**

- Active worktree row is always `"None"` (`SettingsDialog.tsx:669-671` vs `App.tsx:388-390`)
- Add Project / Add Worktree buttons do not render (`SettingsDialog.tsx:600-616`)

**Not the empty-list cause, but real dual-store traps if someone “fixes” Settings by reading native:**

1. Native registry is **not** persistent. The durable list is `ferryx.projects`. After restart App re-registers **only the active** project (`App.tsx:217-224`). Other persisted projects exist in the UI list before they exist in native RAM.
2. No list-projects IPC, so Settings cannot hydrate itself from native.
3. `registerProject`’s canonical return is ignored on the re-register path (`App.tsx:217-224`). A remapped ID (legacy `default` → folder slug) would not empty the list; it can desync IDs.
4. `canonicalizeProjectBootstrap` only rewrites placeholders (`App.tsx:73-75`). Real stored projects stay as-is — again, sidebar would still show them.
