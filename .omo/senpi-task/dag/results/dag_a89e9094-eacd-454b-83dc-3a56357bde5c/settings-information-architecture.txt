## Findings

### Default Agent

- `ui/src/components/SettingsDialog.tsx:1627-1679`
- Current behavior: Agents has a `Default Agent` row with description:
  > “Select the primary CLI coding assistant launched by default.”
- Options are:
  - `Auto` (`defaultAgentId: null`)
  - `None` (`defaultAgentId: "none"`)
  - One button per detected/available agent
- The UI does not explain the distinction between `Auto` and `None`, nor when the default is applied.

**Minimal UI contract:** Add one concise explanation below or within the row:
> “Auto uses the first available enabled agent. None disables automatic agent selection. Choosing an agent always uses that agent when available.”

The wording should reflect the actual runtime semantics; verify those semantics before implementation if they are not already established elsewhere.

- `SettingsDialog.test.tsx:428-475`
- Existing test: `"navigates to Agents section, displays detected agents, configures default agent and overrides"`
- Assert the explanation is present and assert `Auto`, `None`, and explicit agent controls remain available.

### General content

- `SettingsDialog.tsx:246-255`
- Current behavior: General renders only a heading and description:
  > “Desktop shell preferences that follow the compact Ferryx desktop layout.”
- The section is otherwise empty.
- Existing test:
  - `SettingsDialog.test.tsx:275-282`
  - `"keeps General free of the duplicate appearance summary"`

**Minimal UI contract:** General should contain actual general-purpose desktop/app settings, not a placeholder. The smallest coherent correction is either:
1. Remove General from navigation if no general settings are intended, or
2. Keep General and add one clearly owned, functional general setting.

Given the requested IA correction, the cleaner minimal choice is to remove the empty General section and make the initial section the first substantive section (`Appearance`). This avoids presenting an empty destination and avoids duplicating appearance content.

If General must remain, its contract should explicitly define ownership and include at least one functional setting; the current prose-only placeholder is insufficient.

**Focused test seam:** Update:
- `SettingsDialog.test.tsx:167`
  - Remove the General navigation expectation if General is removed.
- `SettingsDialog.test.tsx:275-282`
  - Replace the empty-General test with an assertion that the initial view is the first substantive section, or remove it.
- Add a test that every visible Settings navigation item resolves to a substantive region.

## Recommended smallest coherent IA change

Remove both empty/obsolete destinations from the Settings navigation:

- `General`
- `Quick Commands`

Make `Appearance` the initial section. Keep agent selection under `Agents`, but clarify the meaning of `Default Agent` inline.
