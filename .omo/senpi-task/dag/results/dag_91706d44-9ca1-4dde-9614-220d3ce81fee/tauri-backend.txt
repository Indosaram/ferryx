## 1. Executive Summary & Codebase Health

The Rust backend in `src-tauri/` is well-structured and follows modern Rust idioms (edition 2021, Tauri v2, Tokio 1.43, Axum 0.8, portable-pty 0.8). Architectural separation between OS integration, business domains (terminal, worktree, remote gateway, notifications, browser), and IPC transport layers is clean.

### Core Strengths
- **Strict Concurrency Boundaries:** Clear distinction between fast synchronous memory operations using `parking_lot` and asynchronous runtime orchestration using `tokio`.
- **Durable File I/O & Session Storage:** `session/mod.rs` implements atomic file write patterns (`.json.tmp` -> `sync_all` -> `rename` -> parent directory `sync_all`) with automatic fallback backups on corruption.
- **Git Worktree Isolation:** Robust validation against directory traversal and symlink escapes with strict 1-writer invariants for agent workflows.
- **Off-Thread Blocking Execution:** Synchronous Git operations and filesystem reads are routed through `run_blocking` (`tokio::task::spawn_blocking`), preventing Tokio runtime worker thread starvation.
- **Native OS Security:** Native notification settings and permissions interact with `UNUserNotificationCenter` on macOS via `objc2`, wrapped in exception catches to protect the Rust runtime.

### Module Inter-dependencies & Coupling
- **Terminal -> Output Hub -> Worktree:** Interactive PTY sessions (`PtyManager`) store worktree ownership without holding exclusive writer leases (`src/terminal/session.rs:36-41`). This allows multiple concurrent split panes in the same Git worktree while keeping the writer lease registry free for agent mutations.
- **Remote -> Terminal & Worktree:** The Axum remote server captures a `WorkspaceSnapshotCache` per HTTP request (`src/remote/server.rs:135-180`) to eliminate redundant `git worktree list` subprocess spawning when resolving session metadata.
- **IPC -> Domains:** IPC commands cleanly translate typed inputs into domain operations, offloading blocking synchronous operations onto Tokio's blocking threadpool via `run_blocking` (`src/ipc/mod.rs:11-18`).

## 3. Rust Idioms, Concurrency & Safety Audit

### 3.1 Error Handling & Typing
- **Domain Errors:** Errors are cleanly modelled using `thiserror` (`PtyError` in `src/terminal/mod.rs:4`, `WorktreeError` in `src/worktree/model.rs:126`, `BrowserError` in `src/browser/security.rs:5`, `AuthError` in `src/remote/auth.rs:228`, and `GhosttyConfigError` in `src/terminal/preferences.rs:88`).
- **IPC Boundary Translation:** `IpcError` in `src/ipc/error.rs:44` converts domain errors into machine-readable `IpcErrorCode` enums with structured JSON payloads (`details`), preventing brittle string parsing on the frontend.

### 3.2 Concurrency & Synchronization
- **`parking_lot` vs `tokio::sync`:**
  - In-memory state containers (`PtyManager::sessions`, `TerminalOutputHub::sessions`, `WorkspaceRegistry::workspaces`, `BrowserManager::sessions`, `AuthManager::devices`, `RemoteGatewayState::config`) consistently use `parking_lot::{Mutex, RwLock}`. These locks are short-lived, synchronous, and immune to lock poisoning.
  - Asynchronous boundaries that span `.await` points (e.g., `DaemonClient::connection` in `src/daemon/client.rs:64`) correctly use `tokio::sync::Mutex`.
- **Deadlock Analysis:**
  - `TerminalOutputHub::publish` (`src/terminal/output_hub.rs:84-95`): Safely clones the inner `Arc<RwLock<SessionHub>>` under an outer read lock, drops the outer read guard immediately, and then acquires the inner `write()` lock. This strictly avoids lock inversion or outer write starvation.
  - `WorktreeManager::delete_lock` (`src/worktree/manager.rs:99`): A dedicated mutex serializes destructive operations and lease acquisitions across threads without conflicting with reader leases.

### 3.3 Unsafe Blocks & Foreign Function Interface (FFI)
All `unsafe` blocks across the codebase were audited:
1. `src/daemon/server.rs:21`: `libc::getuid()` — Safe POSIX call to determine current user ID for isolating `/tmp/rorca-{uid}` socket directory.
2. `src/daemon/server.rs:94`: `libc::flock(fd, libc::LOCK_EX | libc::LOCK_NB)` — Safe POSIX advisory lock on the daemon lockfile.
3. `src/terminal/session.rs:217`: `libc::kill(-(pid as i32), sig)` — Sends Unix signal to the PTY process group. *(See Finding W4 regarding sign casting on large PIDs)*.
4. `src/ipc/terminal.rs:388-408`: `macos_proc::get_proc_cwd` calling `proc_pidinfo(pid, PROC_PIDVNODEPATHINFO, ...)` with `MaybeUninit<ProcVnodePathInfo>`. Correctly checks return value before `assume_init()` and guarantees NUL-terminated C string parsing.
5. `src/notification/permission.rs:133, 160`: `objc2` and `block2` FFI calls to `UNUserNotificationCenter`. Wrapped inside `objc2::exception::catch` to ensure Objective-C runtime exceptions do not cause Rust unwinding panics across FFI boundaries.

## 4. Terminal PTY & Daemon Protocol Review

### 4.1 PTY Management & Lifecycle
- `PtyManager` (`src/terminal/pty.rs:29-258`) orchestrates PTY pairs using `portable_pty::native_pty_system()`.
- Spawned processes have their output continuously read on a dedicated `spawn_blocking` thread in 4096-byte chunks (`src/terminal/session.rs:72-88`).
- Process termination is observed via an asynchronous lifecycle watcher loop (`src/terminal/pty.rs:163-228`) polling at 250ms intervals (`LIFECYCLE_POLL_INTERVAL`), with immediate wake-up upon reader completion (`reader_finished` atomic).
- Clean exit sequence: closing I/O master/writer handles, bounded joining of the blocking reader thread (2-second timeout in `join_reader_bounded`), and process reaping via `wait_and_reap` to prevent zombie processes.

### 4.2 Output Hub & Ringbuffer
- `BoundedBuffer` (`src/terminal/output_hub.rs:9-49`) maintains a 512 KiB scrollback buffer per session backed by `VecDeque<Vec<u8>>`.
- Subscribers receive historical snapshots followed by live output over `tokio::sync::broadcast` channels with 1024-message depth.
- Desktop subscribers aggregate outputs with a 32 KiB / 10ms batching loop (`src/ipc/terminal.rs:210-270`) before emitting Tauri events, minimizing IPC serialization overhead.

### 4.3 Daemon Socket Communication & Protocol
- **Daemon Socket Security:** Socket is created at `/tmp/rorca-{uid}/daemon.sock` with directory permissions `0700` and socket file permissions `0600` (`src/daemon/server.rs:20-30, 103-108`).
- **Stale Socket Handling:** Single-instance exclusivity is enforced via `libc::flock` on `/tmp/rorca-{uid}/daemon.lock`. If the lock is acquired and a stale socket file exists, it is automatically unlinked and recreated (`src/daemon/server.rs:90-101`).
- **Binary Data Framing:** The daemon protocol exchanges raw PTY I/O formatted as Base64 strings using a custom Serde helper (`src/daemon/protocol.rs:10-33`), preventing inefficient JSON integer array serialization (`[104, 101, 108, 108, 111]`).

## 5. IPC Command Design Review

### 5.1 Request Validation & Payload Bounds
- All IPC request DTOs enforce `deny_unknown_fields` and `camelCase` naming conventions (`src/ipc/terminal.rs:51`, `src/ipc/worktree.rs:13-33`, `src/ipc/project.rs:104-121`).
- Bounds limits:
  - Custom audio files: 20 MiB ceiling (`MAX_AUDIO_FILE_BYTES` in `src/notification/model.rs:17`).
  - Notification titles & bodies: 80 and 160 characters respectively (`MAX_TITLE_LEN`, `MAX_BODY_LEN` in `src/notification/model.rs:13-15`).
  - URL validations: Only `http://`, `https://`, and `about:blank` schemes are permitted for the embedded browser (`src/browser/security.rs:30-44`).

### 5.2 Threading & Non-Blocking Guarantee
- Every IPC handler executing blocking operations (Git commands, disk I/O, audio decoding) wraps execution in `run_blocking` (`src/ipc/mod.rs:11-18`), which delegates work to Tokio's dedicated blocking thread pool (`spawn_blocking`). This prevents any synchronous I/O or child process waiting from stalling the async reactor.

### Detailed Findings & Suggested Fixes

#### [Critical] C1: Serde field renaming bug on `DaemonStreamMessage` causing test failure
- **Citation:** `src/daemon/protocol.rs:109-126` and `src/daemon/server.rs:444`
- **Issue:** In Serde, `#[serde(rename_all = "camelCase")]` placed on an `enum` only renames the **variant names** (e.g. `Output` -> `output`), but does **NOT** rename the struct fields inside each variant (`session_id` remains `session_id` instead of `sessionId`, and `exit_code` remains `exit_code`). Consequently, `DaemonStreamMessage::Output` and `Exit` emit `session_id` on the wire, violating the camelCase contract expected by clients and causing `test_pump_stream_compact_framing_and_exit` to fail on line 444.
- **Suggested Fix:** Add `#[serde(rename_all = "camelCase")]` to each variant or use variant-level field attributes:
```rust
#[derive(Debug, Clone, Serialize, Deserialize, PartialEq, Eq)]
#[serde(tag = "type", rename_all = "camelCase")]
pub enum DaemonStreamMessage<'a> {
    #[serde(rename_all = "camelCase")]
    Output {
        session_id: Cow<'a, str>,
        #[serde(with = "base64_serde")]
        data: Cow<'a, [u8]>,
    },
    #[serde(rename_all = "camelCase")]
    Lagged {
        session_id: Cow<'a, str>,
        #[serde(with = "base64_serde")]
        history: Cow<'a, [u8]>,
    },
    #[serde(rename_all = "camelCase")]
    Exit {
        session_id: Cow<'a, str>,
        exit_code: Option<i32>,
    },
}
```

#### [Warning] W2: Dead code warnings for `WriterLeaseGuard` and `acquire_writer_lease`
- **Citation:** `src/worktree/manager.rs:57-87` and `src/worktree/manager.rs:268-281`
- **Issue:** `WriterLeaseGuard` and `WorktreeManager::acquire_writer_lease` trigger Rust compiler warnings (`unused struct` and `unused associated items`) during build because caller code currently uses `acquire_writer` and `release_writer` directly.
- **Suggested Fix:** Either adopt RAII-based `acquire_writer_lease` across worktree operations or annotate the struct and method with `#[allow(dead_code)]`.

#### [Warning] W4: Process group signal negation cast risk
- **Citation:** `src/terminal/session.rs:217`
- **Issue:**
```rust
let result = unsafe { libc::kill(-(pid as i32), sig) };
```
If `pid` exceeds `i32::MAX` (e.g. on 64-bit systems with high PID configurations), `pid as i32` becomes negative, and `-(pid as i32)` becomes positive, inadvertently signaling a single process rather than the process group.
- **Suggested Fix:** Validate the PID range before negation:
```rust
let signed_pid = i32::try_from(pid)
    .map_err(|_| PtyError::KillError("PID exceeds i32 range for process group signal".into()))?;
let result = unsafe { libc::kill(-signed_pid, sig) };
```

#### [Warning] W5: Notification settings opener disabled or unsupported
- **Citation:** `src/notification/mod.rs:21-50`
- **Issue:** On macOS in standalone/development mode, `open_system_notification_settings()` always returns `opened: false`, and Linux returns `unsupported`. While understandable during dev mode, production macOS builds should use `x-apple.systempreferences:com.apple.preference.notifications` when packaged inside a `.app` bundle.
- **Suggested Fix:** Check `macos::has_bundle_identity()` and open the system preferences URI when bundled.

#### [Optimization] O1: `BoundedBuffer` chunk fragmentation
- **Citation:** `src/terminal/output_hub.rs:24-35`
- **Issue:** `BoundedBuffer::push` pushes arbitrary `Vec<u8>` slices into a `VecDeque<Vec<u8>>`. During heavy terminal bursts (e.g. `cat large_file.log`), this creates tens of thousands of tiny allocations and deallocations.
- **Suggested Fix:** Implement a contiguous circular byte ringbuffer (`Vec<u8>` with read/write heads) to maintain zero allocations during steady-state terminal scrolling.

---

#### [Optimization] O2: Static CWD Cache eviction leak
- **Citation:** `src/ipc/terminal.rs:22-45`
- **Issue:** `CWD_CACHE` is a static `Mutex<Option<HashMap<String, (Instant, PathBuf)>>>`. Expired entries are only removed if that exact `session_id` is queried again or explicitly closed via `cmd_terminal_close`. Terminals closed abruptly or exited naturally will retain dead session IDs in the cache map.
- **Suggested Fix:** Evict entries older than `CWD_CACHE_TTL` periodically or on `update_cached_cwd`.

---

#### [Optimization] O3: Redundant Git Worktree listing per HTTP request
- **Citation:** `src/remote/server.rs:140-160`
- **Issue:** `WorkspaceSnapshotCache::build` calls `mgr.list_worktrees()` (spawning `git worktree list --porcelain`) synchronously on every remote HTTP request (`list_sessions`, `get_workspace_state`).
- **Suggested Fix:** Cache the worktree list inside `WorktreeManager` with a short TTL (e.g. 1-2 seconds) or invalidate on mutation events.

---

#### [Optimization] O4: Status porcelain parsing allocations
- **Citation:** `src/worktree/git.rs:208-255`
- **Issue:** `parse_status_porcelain` calls `split_whitespace().collect::<Vec<&str>>()` for each line of Git porcelain output, allocating small vectors on every file in large repositories.
- **Suggested Fix:** Use iterator-based indexing or exact byte slicing without vector allocation.

---

#### [Nit] N1: Brand naming discrepancies (`rorca` vs `ferryx`)
- **Citation:** `src/daemon/server.rs:22, 108`, `src/daemon/launchd.rs:5`, `src/lib.rs:25`
- **Issue:** Filesystem paths and logs use `/tmp/rorca-{uid}`, `com.rorca.daemon`, and `"rorca daemon listening..."`, while `Cargo.toml` and Tauri config are named `ferryx`.
- **Suggested Fix:** Standardize internal daemon socket paths, logging identifiers, and plist labels to use a single unified identifier or constant.

---

#### [Nit] N2: Console `eprintln!` in `session/mod.rs`
- **Citation:** `src/session/mod.rs:247, 258`
- **Issue:** Session loading uses raw `eprintln!` on version warnings and corruption recovery rather than `tracing::warn!`.
- **Suggested Fix:** Replace `eprintln!` with `tracing::warn!` for structured logging consistency.

---

#### [Nit] N3: Hardcoded locale environment variables
- **Citation:** `src/ipc/terminal.rs:188-193`
- **Issue:** Terminal spawn hardcodes `LANG`, `LC_ALL`, and `LC_CTYPE` fallback values to `"en_US.UTF-8"`. On systems where `en_US.UTF-8` is not generated (e.g., non-US Linux distros), some CLI tools may emit locale warnings.
- **Suggested Fix:** Fall back to `"C.UTF-8"` if `"en_US.UTF-8"` is unavailable.
