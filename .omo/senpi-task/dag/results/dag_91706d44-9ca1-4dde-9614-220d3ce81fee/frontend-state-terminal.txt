# Frontend State Management & Terminal Orchestration Architecture Review

## Executive Summary

This architecture review evaluates the frontend state machine, terminal orchestration, rendering pipeline, transport abstraction, and persistence layers across `ui/src/state/` and `ui/src/lib/`.

The architecture demonstrates high technical quality with thoughtful optimizations (such as centralized OSC title sniffing for background tabs, a custom animation-frame output scheduler, and an LRU frontend terminal host pool). However, several critical concurrency race conditions, memory leaks, transport deficiencies, and state synchronization bugs exist that impact production stability, memory utilization, and multi-pane session fidelity.

---

## 1. State Management & Stores

### 1.1 Architecture & State Flow
The primary state container is orchestrated through `useWorkspaceStore` (`ui/src/state/workspaceStore.ts`), combining a React reducer (`workspaceReducer`) with mutable synchronous reference mirroring (`stateRef`) and Vite HMR retention (`ui/src/state/hmrWorkspaceState.ts`). Layout tree mutations are delegated to `layoutReducer` (`ui/src/state/layout.ts`) and immutable binary tree operators (`ui/src/state/paneTree.ts`).

```
┌───────────────────────────────────────────────────────────────────┐
│                      useWorkspaceStore                            │
│  - stateRef.current (synchronous update)                          │
│  - reactDispatch(action)                                          │
│  - setHmrWorkspaceState(workspaceId, nextState)                  │
└───────────────┬───────────────────────────────────┬───────────────┘
                │                                   │
      ┌─────────▼─────────┐               ┌─────────▼─────────┐
      │  workspaceReducer │               │   layoutReducer   │
      │  - sessions       │               │   - tabs          │
      │  - worktrees      │               │   - layoutsByTabId│
      │  - activities     │               │   - tabGroups     │
      └───────────────────┘               └─────────┬─────────┘
                                                    │
                                          ┌─────────▼─────────┐
                                          │     paneTree      │
                                          │   (Binary Tree)   │
                                          └───────────────────┘
```

### 1.2 Identified Issues & Architectural Flaws

#### [CRITICAL] Inability to Close Inactive/Parked Worktree Tabs and Panes via Store Actions
- **Location:** `ui/src/state/workspaceStore.ts:375-420`, `ui/src/state/workspaceStore.ts:422-436`
- **Mechanism:** In `useWorkspaceStore`, `closeTab` verifies existence using `snapshot.layout.tabs.find((tab) => tab.id === tabId)`. Similarly, `closePane` only indexes `snapshot.layout.layoutsByTabId?.[tabId]`.
- **Impact:** While `workspaceReducer` explicitly supports closing tabs inside `worktreeLayouts` (`workspaceStore.ts:881-893`), the `closeTab` and `closePane` store callbacks reject any tab not present in the currently active worktree layout. When closing tabs programmatically or via background triggers, tabs in parked worktrees become uncloseable zombies.
- **Remediation:** Query `getAllTabs(snapshot)` or search across both `snapshot.layout` and `snapshot.worktreeLayouts` when resolving the target tab and its associated session references.

#### [WARNING] Concurrency Race in Async `splitPane` upon Worktree Navigation
- **Location:** `ui/src/state/workspaceStore.ts:309-354`
- **Mechanism:** `splitPane` captures `snapshot = stateRef.current` and awaits `services.spawnTerminal(...)`. If the user switches worktrees during this async IPC call, `state.layout` changes. When `dispatch({ type: "SPLIT_PANE", ... })` executes, `layoutReducer` searches `state.layoutsByTabId[action.tabId]` (which is now in `state.worktreeLayouts`). The reducer cannot find the tab, resulting in a no-op state return. The rollback check `if (!stateRef.current.sessions[localSessionId])` then triggers and closes the newly spawned backend terminal.
- **Impact:** Terminal pane splits are aborted and the spawned backend process is killed if the user switches worktrees while the split is spawning.

#### [OPTIMIZATION] Unmemoized Deep State Selectors on Every Store Render
- **Location:** `ui/src/state/workspaceStore.ts:638-640`
- **Mechanism:** `selectAgents(state)`, `selectTabActivitySummaries(state)`, and `selectWorktreeActivitySummaries(state)` are invoked directly on every render of `useWorkspaceStore`.
- **Impact:** Iterates over all tabs, worktrees, sessions, and activity records, allocating new object and array instances on every React render tick regardless of whether underlying state changed.
- **Remediation:** Wrap selector results in `useMemo` keyed on `[state.layout, state.worktreeLayouts, state.sessions, state.activityBySessionId, state.unreadTabIds, state.unreadWorktreePaths]`.

#### [WARNING] `swapLeaves` Disconnects Physical Pane Geometry from Focus State
- **Location:** `ui/src/state/paneTree.ts:135-154`, `ui/src/state/layout.ts:348-361`
- **Mechanism:** `swapLeaves` swaps `leafId` values directly within the tree leaf nodes while leaving `sessionIdsByLeafId` unchanged. As a result, the physical session assigned to the leaf moves, but `activeLeafId` and `expandedLeafId` remain unchanged, causing the active focus highlight to jump across the screen to the opposite physical slot.
- **Remediation:** Either swap the session assignments in `sessionIdsByLeafId` (leaving the tree geometry intact) or update `activeLeafId` / `expandedLeafId` when they match one of the swapped leaf IDs.

#### [NIT] Double HMR Workspace State Writes
- **Location:** `ui/src/state/workspaceStore.ts:119`, `ui/src/state/workspaceStore.ts:125-127`
- **Mechanism:** `dispatch` invokes `setHmrWorkspaceState(workspaceId, nextState)` synchronously, and `useEffect([state, workspaceId])` writes it again immediately after the React render cycle completes.

## 2. Terminal Host & Output Architecture

### 2.1 Architecture & Lifecycle Flow
Terminal lifecycle is decoupled from React mounting via `terminalHostManager` (`ui/src/lib/terminalHostManager.ts`). Inactive terminal instances are retained in a warm LRU cache (`DEFAULT_WARM_CACHE_LIMIT = 2`). Output is processed via a multi-tier pipeline:
1. `terminalEvents.ts`: Global multiplexer receiving raw PTY base64 output from Tauri, decoding stream UTF-8 chunks, sniffing OSC 0/1/2 titles for agent/activity status, and maintaining a 512 KB char circular backlog.
2. `terminalOutputScheduler.ts`: Coalesces incoming output chunks and flushes to `terminal.write` at `requestAnimationFrame` cadence (or immediately upon exceeding `MAX_PENDING_OUTPUT_CHARS = 128 KB`).

```
PTY Stream (Tauri / Remote)
         │
         ▼
TerminalOutputDecoderRegistry (UTF-8 stream decoding)
         │
         ▼
TerminalEventBus (OSC 0/1/2 Parser & 512KB Backlog)
         │
         ├──────────────────────────────┐
         ▼                              ▼
Activity & Title Listeners     attachScheduledOutputSubscription
(Active Agents & Tab Badges)   (Buffer -> rAF / 128KB threshold)
                                        │
                                        ▼
                                 Terminal.write
                                (xterm.js WebGL)
```

### 2.2 Identified Issues & Architectural Flaws

#### [CRITICAL] Memory Leak and Disposed Terminal Addon Attachment in `attachWebglRenderer`
- **Location:** `ui/src/lib/terminalRenderer.ts:31-67`, `ui/src/lib/terminalInstanceFactory.ts:105-108`
- **Mechanism:** In `createTerminalInstance`:
  ```ts
  let disposeWebgl: () => void = () => undefined;
  void attachWebglRenderer(terminal).then((dispose) => {
    disposeWebgl = dispose;
  });
  ```
  `attachWebglRenderer` is an `async` function executing dynamic import `await import("@xterm/addon-webgl")`.
  If `disposeTerminalInstance(inst)` is called before the dynamic import resolves (e.g. rapid tab open/close or LRU eviction):
  1. `inst.disposeWebgl()` invokes the initial no-op closure.
  2. `inst.terminal.dispose()` destroys the terminal.
  3. The dynamic import resolves, instantiates `addon = new WebglAddon()`, and calls `terminal.loadAddon(addon)` on an **already disposed** terminal.
  4. The returned `dispose` function is assigned to the local closure variable and is never called.
- **Impact:** Permanent GPU WebGL context and DOM canvas memory leak on rapid tab open/close cycles or LRU eviction.
- **Remediation:** Pass an `AbortController` signal to `attachWebglRenderer` and check `signal.aborted` or `terminal._core?._isDisposed` before creating or loading the addon.

#### [CRITICAL] Stale Session Closure in Terminal Resize and Input Handlers
- **Location:** `ui/src/lib/terminalInstanceFactory.ts:115`, `ui/src/lib/terminalInstanceFactory.ts:125`
- **Mechanism:** In `createTerminalInstance`:
  ```ts
  const resize = () => {
    cancelAnimationFrame(resizeFrame);
    resizeFrame = requestAnimationFrame(() => {
      ...
      const backendSessionId = session.backendSessionId;
      if (!backendSessionId) return;
      void resizeTerminal({ sessionId: backendSessionId, cols: terminal.cols, rows: terminal.rows });
    });
  };
  ...
  const dataDisposable = terminal.onData((data) => {
    const backendSessionId = session.backendSessionId;
    if (!backendSessionId) return;
    void writeTerminal({ sessionId: backendSessionId, data });
  });
  ```
  Both `resize` and `terminal.onData` capture the initial `session` object passed into `createTerminalInstance`.
  When a session is updated via `terminalHostManager.updateSession(sessionId, newSession)` (e.g. after respawning a dead native PTY during session restore in `App.tsx:273`), `inst.session = newSession` updates the reference on `inst`, but the closures in `resizeObserver` and `terminal.onData` retain the stale `session` reference where `backendSessionId` was `null` or old.
- **Impact:** Keystrokes (`onData`) and window resizes (`fitAddon`) fail or transmit to stale backend PTY session IDs after session reconnection/respawn.
- **Remediation:** Access `getInstance(session.id)?.session.backendSessionId` dynamically inside `onData` and `resize` (matching the pattern used by `onTitleChange` on line 131).

#### [WARNING] Scrollback Truncation on LRU Cache Eviction
- **Location:** `ui/src/lib/terminalHostManager.ts:96-103`, `ui/src/lib/terminalEvents.ts:5`
- **Mechanism:** `DEFAULT_WARM_CACHE_LIMIT` is set to `2`. When a user has more than two inactive tabs, background instances are destroyed via `disposeFrontendInstance`. When switching back, a new terminal is constructed and hydrated with `terminalEventBus.subscribeOutput(..., replay = true)`.
  However, `terminalEventBus` caps backlog at `MAX_BACKLOG_CHARS = 512 * 1024` (512 KB), whereas `DEFAULT_TERMINAL_SETTINGS.scrollback` is 10,000 lines (~1–5 MB).
- **Impact:** Switching between 3 or more tabs silently destroys earlier terminal scrollback history beyond 512 KB.
- **Remediation:** Provide configurable backlog sizing matching user scrollback preferences, or store structured scrollback in a dedicated buffer manager.

#### [OPTIMIZATION] `findPartialOscPrefix` and `publishOutput` Micro-Allocations
- **Location:** `ui/src/lib/terminalEvents.ts:66-72`, `ui/src/lib/terminalEvents.ts:154-166`
- **Mechanism:** `findPartialOscPrefix` allocates and sorts an array on every output chunk: `[...OSC_PARTIAL_PREFIXES].sort(...)`. Additionally, `publishOutput` uses `entry.chunks.shift()` in a loop to trim excess backlog, incurring $O(N^2)$ memory copying under high chunk counts.
- **Remediation:** Pre-sort `OSC_PARTIAL_PREFIXES` as a static constant; use an index pointer or circular ring buffer for backlog chunk eviction.

## 3. Terminal Transport Layer

### 3.1 Architecture & Transport Contracts
The transport layer (`ui/src/lib/terminalTransport/`) defines an abstract contract `TerminalTransport` (`types.ts`) with two implementations:
- `TauriTerminalTransport` (`tauriTransport.ts`): Bridges to Rust Tauri IPC via `@tauri-apps/api`.
- `WebSocketTerminalTransport` (`remoteTransport.ts`): Bridges to remote daemon instances over WebSocket.

```
                  ┌────────────────────────┐
                  │   TerminalTransport    │ (Interface)
                  └───────────┬────────────┘
                              │
             ┌────────────────┴────────────────┐
             ▼                                 ▼
┌─────────────────────────┐       ┌─────────────────────────┐
│ TauriTerminalTransport  │       │ WebSocketTerminalTransport│
│ - listSessions()        │       │ - listSessions()        │
│ - attach()              │       │ - attach()              │
│ - write() / resize()    │       │ - write() / resize()    │
│ - onOutput()            │       │ - onOutput()            │
│ - onLifecycle()         │       │ - onLifecycle() (STUB)  │
└─────────────────────────┘       └─────────────────────────┘
```

### 3.2 Identified Issues & Architectural Flaws

#### [CRITICAL] Complete Absence of Reconnection, Heartbeat, and Error Recovery in `WebSocketTerminalTransport`
- **Location:** `ui/src/lib/terminalTransport/remoteTransport.ts:1-93`
- **Mechanism:** `WebSocketTerminalTransport` creates raw `new WebSocket(wsUrl)` instances without attaching `onerror` or `onclose` handlers. It lacks ping/pong heartbeats, reconnect loops, backoff mechanisms, or reconnection token negotiations.
- **Impact:** Any transient network interruption terminates remote terminal connectivity permanently with no UI feedback or recovery.

#### [CRITICAL] Unimplemented `onLifecycle` in `WebSocketTerminalTransport`
- **Location:** `ui/src/lib/terminalTransport/remoteTransport.ts:89-91`
- **Mechanism:** `onLifecycle` is a stub returning a no-op cleanup:
  ```ts
  onLifecycle(_listener: (event: { sessionId: string; state: string; exitCode?: number | null }) => void): Unsubscribe {
    return () => {};
  }
  ```
- **Impact:** Remote daemon session exits, crashes, and process failures are never dispatched to the state machine. `WorkspaceStore` retains sessions indefinitely in the `"working"` state.

#### [WARNING] Silent Data Loss During WebSocket Connection Handshake
- **Location:** `ui/src/lib/terminalTransport/remoteTransport.ts:48-64`
- **Mechanism:** Methods `write`, `resize`, and `signal` check `if (!ws || ws.readyState !== WebSocket.OPEN) return;`.
- **Impact:** If `write()` or `resize()` is called immediately following `attach()` while `ws.readyState === WebSocket.CONNECTING`, data and initial resize geometry are silently dropped.
- **Remediation:** Implement an outgoing queue that flushes upon the WebSocket `open` event.

#### [WARNING] WebSocket Socket Leak on Repeated `attach()`
- **Location:** `ui/src/lib/terminalTransport/remoteTransport.ts:21-46`
- **Mechanism:** Calling `attach(sessionId)` repeatedly overwrites `this.sockets.set(sessionId, ws)` without closing the previously existing socket.
- **Impact:** Orphaned WebSocket connections remain open in the browser, consuming network sockets and continuing to deliver duplicate output frames to registered listeners.

#### [OPTIMIZATION] Redundant Tauri IPC Event Subscriptions in `TauriTerminalTransport`
- **Location:** `ui/src/lib/terminalTransport/tauriTransport.ts:37-77`
- **Mechanism:** Every call to `onOutput(sessionId, listener)` registers a new Tauri IPC listener (`onTerminalOutput`), filtering client-side by `payload.sessionId === sessionId`.
- **Impact:** With $M$ active terminal panes, $M$ separate IPC event handlers receive all PTY output events across the Tauri bridge.
- **Remediation:** Multiplex through a single centralized listener (as implemented in `terminalEvents.ts`).

## 4. State Synchronization & Persistence

### 4.1 Persistence Mechanics & Serialization
Session persistence (`ui/src/lib/sessionPersistence.ts`) serializes worktrees, active and parked layouts, tab groups, split pane trees, and terminal session metadata to local storage and Tauri backend files (`ferryx.projects`, `loadSession`, `saveSession`).

### 4.2 Identified Issues & Architectural Flaws

#### [WARNING] Git Branch Ref Corruption During State Deserialization
- **Location:** `ui/src/lib/sessionPersistence.ts:187`
- **Mechanism:** During worktree deserialization:
  ```ts
  branch: wt.branch ? (wt.branch.startsWith("refs/heads/") ? wt.branch : `refs/heads/${wt.branch}`) : null,
  ```
  If `wt.branch` is a tag (`refs/tags/v1.0.0`), a remote tracking branch (`refs/remotes/origin/feature`), or a custom ref, this logic prepends `refs/heads/` (e.g. `refs/heads/refs/tags/v1.0.0`).
- **Impact:** Corrupts non-standard Git refs and detached HEAD references across app restarts.
- **Remediation:** Check if `wt.branch` contains `refs/` or is detached before prepending `refs/heads/`.

#### [WARNING] Missing Leaf Session ID Collision on Restored Split Trees
- **Location:** `ui/src/lib/sessionPersistence.ts:251-255`
- **Mechanism:** When deserializing a split pane tree where `persistedMapping` is missing entries for specific leaves:
  ```ts
  const sessionIdsByLeafId = persistedMapping && Object.keys(persistedMapping).length > 0
    ? Object.fromEntries(leafIds.map((leafId) => [leafId, persistedMapping[leafId] ?? primarySessionId]))
    : Object.fromEntries(leafIds.map((leafId) => [leafId, primarySessionId]));
  ```
  If multiple missing leaves fallback to `primarySessionId`, multiple split panes bind to the identical session ID.
- **Impact:** Keystrokes, output, and focus state become cross-wired between multiple panes within the same tab.
- **Remediation:** Synthesize unique fallback session IDs or prune unmapped leaves from the restored tree.

#### [NIT] Unmapped Settings Storage Keys in Migration Table
- **Location:** `ui/src/lib/storageKeys.ts:11-19`
- **Mechanism:** `LEGACY_STORAGE_KEY_MAP` maps legacy `orca.*` and `rorca.*` keys for projects, sidebar, and notifications, but omits `APPEARANCE_SETTINGS_STORAGE_KEY` and `BROWSER_SETTINGS_STORAGE_KEY`.

## 6. Concrete Remediation Code Snippets

### Remediation for ISSUE-01 (WebGL Addon Race & Leak)
`ui/src/lib/terminalInstanceFactory.ts`:
```ts
// Attach WebGL with cancellation signal tied to instance disposal
const webglAbortController = new AbortController();
let disposeWebgl: () => void = () => undefined;

void attachWebglRenderer(terminal, webglAbortController.signal).then((dispose) => {
  if (webglAbortController.signal.aborted) {
    dispose();
  } else {
    disposeWebgl = dispose;
  }
});

// Inside disposeTerminalInstance:
export function disposeTerminalInstance(inst: TerminalInstance): void {
  inst.webglAbortController?.abort();
  inst.disposeWebgl();
  inst.resizeObserver.disconnect();
  inst.unsubscribeOutput?.();
  inst.unsubscribeOutput = undefined;
  for (const d of inst.disposables) d();
  inst.searchAddon.dispose();
  inst.terminal.dispose();
  inst.element.remove();
}
```

### Remediation for ISSUE-05 (Closing Parked Worktree Tabs)
`ui/src/state/workspaceStore.ts`:
```ts
const closeTab = useCallback(
  async (tabId: string) => {
    const snapshot = stateRef.current;
    const allTabs = getAllTabs(snapshot);
    const closingTab = allTabs.find((tab) => tab.id === tabId);
    if (!closingTab || closingTab.pinned) return;

    if (closingTab.kind === "browser") {
      await closeBrowser(closingTab.browserId);
      dispatch({ type: "CLOSE_TAB", tabId });
      return;
    }

    const closingSession = snapshot.sessions[closingTab.sessionId];
    const disposableSessions = getDisposableSessionsForTab(snapshot, tabId);
    const tabSessionIds = getTabSessionIds(snapshot, tabId);

    const isInActiveLayout = snapshot.layout.tabs.some((tab) => tab.id === tabId);
    if (isInActiveLayout && snapshot.layout.tabs.length === 1) {
      const closingWorktreePath = sessionWorktreePath(closingSession);
      const worktree =
        (closingWorktreePath && snapshot.worktrees.find((candidate) => candidate.path === closingWorktreePath)) ??
        getActiveWorktree(snapshot);
      if (!worktree) return;

      await Promise.all(
        disposableSessions.map((session) => closeBackendSessionAndWait(session, services)),
      );
      for (const sessionId of tabSessionIds) {
        if (!isSessionReferencedOutsideTab(snapshot, sessionId, tabId)) {
          terminalHostManager.destroy(sessionId);
        }
      }
      const replacement = await createSpawnedTab(worktree, closingTab.label);
      dispatch({ type: "CLOSE_TAB", tabId, replacement });
      return;
    }

    dispatch({ type: "CLOSE_TAB", tabId });
    for (const sessionId of tabSessionIds) {
      if (!isSessionReferencedOutsideTab(snapshot, sessionId, tabId)) {
        terminalHostManager.destroy(sessionId);
      }
    }
    await Promise.allSettled(disposableSessions.map((session) => closeBackendSession(session, services)));
  },
  [createSpawnedTab, dispatch, services],
);
```
