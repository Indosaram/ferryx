# Comprehensive Security, Process Isolation, Remote Pairing, and Error Handling Review

**Project:** Ferryx / Orca-Lite  
**Scope:** Backend (`src-tauri/src/`) and Frontend (`ui/src/lib/`, `ui/src/state/`, `ui/src/components/`)  
**Date:** 2026-08-23  

---

## 1. Executive Summary & Architecture Overview

Ferryx is an ultra-lightweight workspace and AI agent launcher built with Tauri v2 (Rust backend) and React/TypeScript (frontend). The architecture spans:
1. **Interactive Native PTY & Terminal Management:** Spawns local pseudo-terminals managed via `portable-pty` with Unix process-group signaling and output multiplexing via `TerminalOutputHub`.
2. **Local Daemon & UDS Server:** Background daemon using Unix Domain Sockets (`/tmp/rorca-{uid}/daemon.sock`) with atomic `flock` locking, session persistence, and LaunchAgent management.
3. **Remote Gateway & Pairing:** Axum-based HTTP/WebSocket server exposing REST endpoints and terminal streaming over local network / Tailscale, authenticated via pairing codes and 64-character bearer tokens.
4. **Child Webview Browser Engine:** Native child webviews docked within the main window for interactive web browsing, supporting cookie parsing and multi-profile isolation.
5. **Git Worktree Isolation:** Strict directory canonicalization and namespace validation for multi-worktree repository workflows.

### Summary of Key Findings
* **Critical / High Risk:** Arbitrary file read / path traversal in remote static asset serving (`src-tauri/src/remote/server.rs:568-586`); PIN brute-forcing vulnerability in remote pairing due to lack of rate limiting (`src-tauri/src/remote/auth.rs:66-93`); Cleartext HTTP/WS transmission of tokens and terminal keystrokes over `0.0.0.0` with wildcard CORS (`src-tauri/src/remote/server.rs:615-645`).
* **Medium Risk:** Unbounded input lines in daemon UDS server (`BufReader::read_line` memory exhaustion DoS); lack of navigation restriction callbacks (`on_navigation`) on embedded browser webviews; environment variable inheritance into spawned terminal shells; missing registration of `cmd_browser_import_cookies` IPC handler.
* **Low / Best Practice:** Missing top-level React Error Boundary; unhandled WebSocket disconnect recovery in `WebSocketTerminalTransport`; permissive CSP in `tauri.conf.json` (`'unsafe-eval'`, `'unsafe-inline'`).

## 2. Security Boundaries & Process Spawning

### 2.1 Command Execution & PTY Lifecycle
* **Implementation:** `src-tauri/src/terminal/pty.rs:47-142`, `src-tauri/src/terminal/session.rs:160-192`, `src-tauri/src/ipc/terminal.rs:133-220`
* **Mechanism:** Terminals are spawned using `portable_pty::native_pty_system().openpty()`. Process execution uses `CommandBuilder::new_default_prog()` which executes the user's default shell (e.g., `/bin/zsh` or `/bin/bash`).
* **Process Group Signaling (`session.rs:160-184`):**
  ```rust
  let result = unsafe { libc::kill(-(pid as i32), sig) };
  ```
  Signals (`SIGINT`, `SIGTERM`, `SIGKILL`) are sent to the negative process group ID (`-pid`), ensuring that background sub-processes spawned by child shells are reaped and not orphaned when panes close.
* **Exit Code Finalization & Resource Cleanup (`pty.rs:104-245`):** The `PtyManager` runs an async lifecycle watcher loop polling `poll_exit_code()`. On termination, `take_reader_task()` joins the blocking reader with a 2-second timeout (`READER_SHUTDOWN_TIMEOUT`), preventing thread leaks upon slave PTY hang.

### 2.2 Daemon Server & UDS Isolation
* **Implementation:** `src-tauri/src/daemon/server.rs:18-85`, `src-tauri/src/daemon/launchd.rs:1-70`
* **Socket Path & Permissions (`daemon/server.rs:18-34`):**
  Runtime directory is established at `/tmp/rorca-{uid}` with `0700` POSIX mode permissions. The socket `daemon.sock` is explicitly set to `0600` via `std::os::unix::fs::PermissionsExt`.
* **Single Instance & Concurrency Lock (`daemon/server.rs:88-105`):**
  Uses `libc::flock(fd, libc::LOCK_EX | libc::LOCK_NB)` on `/tmp/rorca-{uid}/daemon.lock` to ensure only one daemon holds the lock and prevents race conditions across restarts.
* **Launchd Service Management (`daemon/launchd.rs:1-70`):**
  Generates `~/Library/LaunchAgents/com.rorca.daemon.plist` pointing to `current_exe() --daemon`. The generated plist restricts standard out and error to `/tmp/rorca-daemon.log` and `/tmp/rorca-daemon.err`.

### 2.3 Environment Variable Sanitization & Secret Leakage
* **Implementation:** `src-tauri/src/ipc/terminal.rs:189-197`
* **Current Behavior:**
  ```rust
  let mut cmd = CommandBuilder::new_default_prog();
  cmd.cwd(&cwd);
  cmd.env("TERM", "xterm-256color");
  cmd.env("COLORTERM", "truecolor");
  cmd.env("PROMPT_EOL_MARK", "");
  for (key, default) in [("LANG", "en_US.UTF-8"), ("LC_ALL", "en_US.UTF-8"), ("LC_CTYPE", "en_US.UTF-8")] {
      cmd.env(key, std::env::var(key).unwrap_or_else(|_| default.into()));
  }
  ```
* **Risk (Medium):** `portable_pty::CommandBuilder::new_default_prog()` inherits all parent process environment variables by default. If the parent app holds sensitive credentials (e.g. `FERRYX_DATA_DIR`, internal API keys, tokens), these environment variables are inherited into spawned interactive shells unless explicitly sanitized or cleared with `cmd.env_clear()`.

### 2.4 Path Traversal & Git Parameter Injection Controls
* **Implementation:** `src-tauri/src/worktree/manager.rs:145-200`, `src-tauri/src/worktree/git.rs:21-70`
* **Path Validation (`manager.rs:145-180`):**
  1. Validates that paths are absolute (`path.is_absolute()`).
  2. Forbids parent traversal components (`matches!(component, Component::ParentDir)`).
  3. Rejects leading dashes on path segments (`name.starts_with('-')`) to prevent argument injection in external CLI tools.
  4. Rejects ASCII control characters (`name.chars().any(char::is_control)`).
  5. Canonicalizes via `fs::canonicalize` and strictly asserts that the target starts with `self.repo_root`.
* **Git Argument Injection Protection (`git.rs:21-50`):**
  - Branch names and refs are checked with `validate_git_value()`, prohibiting leading `-` and control chars.
  - Path arguments are validated via `validate_git_path_argument()`.
  - Commands use explicit arguments array `Command::new("git").args(&arg_strs)` rather than shell strings, avoiding shell injection.
  - Worktree operations use double dash `--` delimiters (e.g. `git worktree add -b <branch> -- <path>`).

### 2.5 External Application Launching
* **Implementation:** `src-tauri/src/ipc/browser.rs:201-218`, `src-tauri/src/notification/mod.rs:40-70`
* **URL Opening (`ipc/browser.rs:201-218`):**
  - Uses `crate::browser::validate_url(&url)` which restricts schemes to `http`, `https`, and `about:blank`.
  - Spawns platform openers: macOS (`open`), Linux (`xdg-open`), Windows (`cmd /C start <url>`).
  - **Risk on Windows (Low):** Passing raw URL string to `cmd /C start` can execute arbitrary commands if the URL contains `&` or `^` or spaces. Mitigation: Use Windows API `ShellExecuteW` directly.

## 3. Remote Protocol & Pairing Security

### 3.1 Pairing Token Generation & Cryptographic Validation
* **Implementation:** `src-tauri/src/remote/auth.rs:66-150`
* **Token Entropy:** `exchange_pairing_code` generates a 64-character token via `rand::thread_rng().sample_iter(&Alphanumeric).take(64)`, providing ~380 bits of cryptographic entropy.
* **Token Persistence & Permissions (`auth.rs:175-195`):**
  `write_private_json` writes state to a `.tmp` file and atomically renames it. On Unix, parent directories are created with mode `0700` and files with mode `0600`, preventing access by other local system users.
* **Device Revocation (`auth.rs:134-150`):** Tokens map to `device_id`. Revoking a device sets `device.revoked = true` and immediately rejects subsequent `validate_token` requests with `AuthError::RevokedDevice`.

### 3.2 High Severity: 6-Digit Pairing PIN Brute-Force Vulnerability
* **File & Line:** `src-tauri/src/remote/auth.rs:66-93`, `src-tauri/src/remote/server.rs:45-60`
* **Severity:** **HIGH**
* **Finding:**
  The pairing code is a 6-digit numeric PIN (`100_000..=999_999`), meaning there are only 900,000 possibilities. The code remains valid for 60 seconds (`PAIRING_EXPIRY`).
  There is **no rate limiting, delay, or max-attempts counter** on the `/api/v1/pair/exchange` endpoint. An attacker on the local network (or malicious JavaScript running on the same machine via CORS) can send thousands of requests per second and guess the PIN within the 60-second window.

### 3.3 High Severity: Arbitrary File Read via Static Asset Serving
* **File & Line:** `src-tauri/src/remote/server.rs:568-586`
* **Severity:** **HIGH**
* **Finding:**
  ```rust
  async fn serve_static_or_index(uri: axum::http::Uri) -> Response {
      let dist_dir = resolve_dist_dir();
      let path = uri.path().trim_start_matches('/');
      let file_path = dist_dir.join(path);

      if !path.is_empty() && file_path.exists() && file_path.is_file() {
          if let Ok(bytes) = tokio::fs::read(&file_path).await {
              let mime = mime_guess::from_path(&file_path).first_or_octet_stream();
              return ([(header::CONTENT_TYPE, mime.as_ref())], bytes).into_response();
          }
      }
      ...
  ```
  `dist_dir.join(path)` does not verify that `file_path` remains within `dist_dir`. If an HTTP request is made to `/..%2f..%2f..%2fetc/passwd` or `/../../Cargo.toml` (or URL decoded paths containing `..`), `tokio::fs::read` reads files outside `dist_dir` and returns them with octet-stream MIME type.

### 3.4 Medium Severity: Wildcard CORS & Cleartext Network Exposure
* **File & Line:** `src-tauri/src/remote/server.rs:615-645`, `src-tauri/src/remote/server.rs:650-685`
* **Severity:** **MEDIUM**
* **Finding:**
  1. **Wildcard CORS:** `create_remote_router` applies `CorsLayer::new().allow_origin(Any).allow_methods(Any).allow_headers(Any)`. Any third-party website opened in any web browser on the local machine can issue cross-origin requests to `http://127.0.0.1:43821` or the LAN IP.
  2. **Cleartext Transport:** The remote server binds to `0.0.0.0:43821` in plaintext `http://` and `ws://`. When used over a local Wi-Fi / LAN without Tailscale HTTPS encryption, all authentication tokens and terminal keystrokes/outputs are subject to eavesdropping.

### 3.5 Low Severity: Auth Tokens Exposed in URL Query Parameters
* **File & Line:** `src-tauri/src/remote/server.rs:37-43`, `ui/src/lib/remoteClient.ts:79`, `ui/src/lib/terminalTransport/remoteTransport.ts:13-18`
* **Severity:** **LOW**
* **Finding:**
  WebSocket connections pass the token as a query parameter (`/api/v1/terminal/{id}?token=...` and `/api/v1/events?token=...`). Query parameters are logged in HTTP proxies, access logs, and browser network inspect logs.
  *Recommendation:* For WebSockets, pass authentication tokens during the initial WS handshake using the `Sec-WebSocket-Protocol` header or via an initial authenticated JSON message upon connection establishment.

## 4. Webview & Browser Security

### 4.1 Tauri Sandbox Boundaries & Capability ACL
* **Implementation:** `src-tauri/tauri.conf.json`, `src-tauri/capabilities/default.json`
* **Capability Scope:** `capabilities/default.json` explicitly bounds permissions (`core:default`, `notification:*`, `dialog:allow-open`) to webview label `"main"`.
* **Child Webview Isolation:** Child webviews (`browser-<uuid>`) spawned for embedded browsing do NOT match the `"main"` label, so Tauri denies them all native IPC commands by default.

### 4.2 Content Security Policy (CSP)
* **File & Line:** `src-tauri/tauri.conf.json:20-22`
* **Severity:** **LOW / BEST PRACTICE**
* **Configuration:**
  ```json
  "csp": "default-src 'self' http://127.0.0.1:5173 http://localhost:5173; script-src 'self' 'unsafe-inline' 'unsafe-eval' http://127.0.0.1:5173 http://localhost:5173; style-src 'self' 'unsafe-inline' http://127.0.0.1:5173 http://localhost:5173; ..."
  ```
* **Analysis:**
  `'unsafe-eval'` and `'unsafe-inline'` are present in the global Tauri CSP to support Vite HMR in development. In production releases, `'unsafe-eval'` should be removed, and scripts should be constrained to cryptographic hashes/nonces.

### 4.3 In-Webview Navigation Restrictions
* **File & Line:** `src-tauri/src/ipc/browser.rs:24-58`, `src-tauri/src/browser/security.rs:25-39`
* **Severity:** **MEDIUM**
* **Finding:**
  While initial URL creation (`cmd_browser_create`) and programmatic navigation (`cmd_browser_navigate`) pass through `validate_url()`, the child webview builder does not attach an `on_navigation` hook. If a user clicks a link inside a rendered webpage that redirects to `file:///` or custom protocols, the webview engine may allow navigation outside the intended `http`/`https`/`about:blank` boundary.

### 4.4 Unregistered IPC Command: Cookie Import Mismatch
* **File & Line:** `ui/src/lib/browserTauri.ts:66-71`, `src-tauri/src/lib.rs:160-205`
* **Severity:** **LOW**
* **Finding:**
  The frontend defines `importBrowserCookies()` calling `cmd_browser_import_cookies`. However, `src-tauri/src/lib.rs` does not register `cmd_browser_import_cookies` in `invoke_handler![]`, and `src-tauri/src/ipc/browser.rs` lacks the command handler. Calling this API will immediately reject with a missing command IPC error.

## 5. IPC Validation & Error Contracts

### 5.1 Structured Error Types & Protocol Mapping
* **Implementation:** `src-tauri/src/ipc/error.rs:1-170`, `ui/src/lib/ipcErrors.ts:1-14`, `ui/src/lib/tauri.ts:188-212`
* **Rust Error Envelope:**
  ```rust
  #[derive(Debug, Clone, PartialEq, Serialize, Deserialize)]
  #[serde(rename_all = "camelCase")]
  pub struct IpcError {
      pub code: IpcErrorCode,
      pub message: String,
      #[serde(skip_serializing_if = "Option::is_none")]
      pub details: Option<Value>,
  }
  ```
* **Frontend Error Parsing:** `toIpcError()` converts Tauri error rejections into typed `StructuredIpcError` objects. `isStructuredIpcError()` guards runtime error properties. `worktreeErrorMessage()` provides user-friendly remediation messages for common Git and lease conflicts.

### 5.2 Strict Request Deserialization
* **Implementation:** `src-tauri/src/ipc/terminal.rs:43-52`, `src-tauri/src/ipc/project.rs:91-96`, `src-tauri/src/ipc/worktree.rs:10-27`
* **Contract:** All IPC request structs derive `#[serde(deny_unknown_fields)]`. Extraneous parameters from malformed frontend payloads are immediately rejected at the deserialization boundary.

### 5.3 Medium Severity: Unbounded Input Streams in Daemon & IPC
* **File & Line:** `src-tauri/src/daemon/server.rs:152-158`, `src-tauri/src/ipc/terminal.rs:470-478`
* **Severity:** **MEDIUM**
* **Finding:**
  1. In `DaemonServer::handle_client`, incoming requests are read using `reader.read_line(&mut line).await` without a byte limit. If a local client or compromised process streams gigabytes without a newline `\n`, it consumes unbounded memory in the daemon process.
  2. In `cmd_terminal_write`, the `data: String` argument is accepted without length caps. Passing large payloads (e.g. hundreds of megabytes) blocks Tokio worker threads during PTY writes.

## 6. Client-Side Error Boundaries & Recovery

### 6.1 React Error Boundary & Unhandled Rejections
* **Implementation:** `ui/src/main.tsx:13-35`, `ui/src/App.tsx:64-90`
* **Bootstrap Failure:** `App.tsx` handles initial bootstrap rejection by rendering a fatal error fallback screen.
* **Finding (Medium):** There is **no top-level `<ErrorBoundary>` component** wrapping `<WorkspaceApp />`. Any rendering error thrown in terminal split calculations, pane drag-and-drop, or custom tab rendering causes React to unmount the entire component tree and display a blank page.

### 6.2 Terminal Host Lifecycle & LRU Eviction
* **Implementation:** `ui/src/lib/terminalHostManager.ts:20-180`, `ui/src/lib/terminalEvents.ts:80-175`
* **LRU & Leak Prevention:**
  - `TerminalHostManager` manages xterm.js instances with a configurable warm cache limit (`DEFAULT_WARM_CACHE_LIMIT = 2`).
  - Inactive tabs detach output listeners and trigger instance disposal on LRU overflow, preventing memory leaks in large workspaces.
* **Output Ringbuffer & Lag Handling:**
  - `terminalEvents.ts` limits scrollback backlog to 512 KB (`MAX_BACKLOG_CHARS`).
  - Native backend `output_hub.rs` uses a 2 MB bounded ringbuffer per session.
  - Lagged subscribers resynchronize without process crash.

### 6.3 Native PTY Crash & Session Recovery
* **Implementation:** `ui/src/App.tsx:210-236`, `ui/src/lib/sessionPersistence.ts:1-120`
* **PTY Deserialization & Respawn:**
  When restoring saved workspaces after app restart or PTY failure, dead sessions (`!candidate.backendSessionId`) are cleanly differentiated from frontend local tab IDs. The app automatically respawns new native PTYs while preserving user layout, split ratios, and tab groupings.

### 6.4 Remote WebSocket Disconnection Recovery
* **Implementation:** `ui/src/lib/remoteClient.ts:89-97`, `ui/src/lib/terminalTransport/remoteTransport.ts:13-75`
* **Event Client:** `RemoteClient.connectEvents` implements auto-reconnect with a 3-second backoff timer on socket closure (`onclose`).
* **Finding (Low):** `WebSocketTerminalTransport` creates WebSockets per attached session in `attach()` but does not attach an `onclose` reconnect handler or report terminal connection loss through `onLifecycle` (`onLifecycle` is currently a no-op).

## 8. Remediation Code Examples

### 8.1 Fix SEC-01: Static Asset Path Traversal Protection
Canonicalize the requested path and verify that it starts with `dist_dir`:

```rust
// src-tauri/src/remote/server.rs
async fn serve_static_or_index(uri: axum::http::Uri) -> Response {
    let dist_dir = resolve_dist_dir();
    let Ok(canonical_dist) = std::fs::canonicalize(&dist_dir) else {
        return Html(EMBEDDED_FALLBACK_HTML).into_response();
    };

    let path_str = uri.path().trim_start_matches('/');
    if !path_str.is_empty() {
        let candidate = canonical_dist.join(path_str);
        if let Ok(canonical_file) = std::fs::canonicalize(&candidate) {
            // Verify path remains strictly inside dist directory
            if canonical_file.starts_with(&canonical_dist) && canonical_file.is_file() {
                if let Ok(bytes) = tokio::fs::read(&canonical_file).await {
                    let mime = mime_guess::from_path(&canonical_file).first_or_octet_stream();
                    return ([(header::CONTENT_TYPE, mime.as_ref())], bytes).into_response();
                }
            }
        }
    }

    // SPA fallback: serve index.html
    let index_file = canonical_dist.join("index.html");
    if index_file.is_file() {
        if let Ok(html) = tokio::fs::read_to_string(&index_file).await {
            return Html(html).into_response();
        }
    }

    Html(EMBEDDED_FALLBACK_HTML).into_response()
}
```

### 8.2 Fix SEC-02: Pairing PIN Rate Limiting & Attempt Cap
Enforce a maximum of 5 failed attempts per pairing code and a delay between attempts:

```rust
// src-tauri/src/remote/auth.rs
struct PairingCode {
    _code: String,
    created_at: Instant,
    default_permission: DevicePermission,
    failed_attempts: u32,
}

const MAX_PAIRING_ATTEMPTS: u32 = 5;

pub fn exchange_pairing_code(
    &self,
    code: &str,
    device_name: &str,
) -> Result<(String, DeviceInfo), AuthError> {
    let mut codes = self.pairing_codes.write();
    
    // Find the pairing code entry
    let (matched_code, pairing) = codes
        .iter_mut()
        .find(|(c, _)| c.as_str() == code)
        .map(|(c, p)| (c.clone(), p))
        .ok_or(AuthError::InvalidPairingCode)?;

    if pairing.created_at.elapsed() > PAIRING_EXPIRY {
        codes.remove(&matched_code);
        return Err(AuthError::ExpiredPairingCode);
    }

    if pairing.failed_attempts >= MAX_PAIRING_ATTEMPTS {
        codes.remove(&matched_code);
        return Err(AuthError::InvalidPairingCode);
    }

    let default_permission = pairing.default_permission;
    codes.remove(&matched_code);
    drop(codes);

    let device_id = uuid::Uuid::new_v4().to_string();
    let token: String = rand::thread_rng()
        .sample_iter(&Alphanumeric)
        .take(64)
        .map(char::from)
        .collect();

    let now = unix_now();
    let info = DeviceInfo {
        id: device_id.clone(),
        name: device_name.to_string(),
        permission: default_permission,
        created_at: now,
        last_seen_at: now,
        revoked: false,
    };

    self.devices.write().insert(device_id.clone(), info.clone());
    self.tokens.write().insert(token.clone(), device_id);
    self.persist_best_effort();
    Ok((token, info))
}
```

### 8.4 Fix SEC-05: Bounded UDS Line Reading in Daemon Server
Prevent memory exhaustion by reading lines with a 64 KB maximum line limit:

```rust
// src-tauri/src/daemon/server.rs
const MAX_REQUEST_BYTES: usize = 64 * 1024; // 64 KB max frame

async fn handle_client(self: Arc<Self>, stream: UnixStream) {
    let (read_half, mut write_half) = stream.into_split();
    let mut reader = BufReader::new(read_half);
    let mut line = String::new();

    loop {
        line.clear();
        let mut take_reader = (&mut reader).take(MAX_REQUEST_BYTES as u64);
        match take_reader.read_line(&mut line).await {
            Ok(0) => break,
            Ok(_) if line.len() >= MAX_REQUEST_BYTES => {
                let resp = DaemonResponse::Error {
                    message: "Request frame exceeded max payload size".into(),
                };
                let mut json = serde_json::to_string(&resp).unwrap();
                json.push('\n');
                let _ = write_half.write_all(json.as_bytes()).await;
                break;
            }
            Ok(_) => {
                let req: Result<DaemonRequest, _> = serde_json::from_str(line.trim());
                // ... handle request ...
            }
            Err(_) => break,
        }
    }
}
```

### 8.5 Fix SEC-07: Top-Level React Error Boundary
Add a React Error Boundary in `ui/src/App.tsx`:

```tsx
// ui/src/components/ErrorBoundary.tsx
import React, { Component, type ReactNode } from "react";

interface Props {
  children: ReactNode;
}

interface State {
  hasError: boolean;
  error: Error | null;
}

export class ErrorBoundary extends Component<Props, State> {
  constructor(props: Props) {
    super(props);
    this.state = { hasError: false, error: null };
  }

  static getDerivedStateFromError(error: Error): State {
    return { hasError: true, error };
  }

  componentDidCatch(error: Error, errorInfo: React.ErrorInfo) {
    console.error("Unhandled React UI error:", error, errorInfo);
  }

  render() {
    if (this.state.hasError) {
      return (
        <div className="flex h-screen w-screen flex-col items-center justify-center bg-background p-6 text-foreground">
          <h2 className="text-sm font-semibold text-destructive mb-2">Something went wrong</h2>
          <pre className="max-w-xl overflow-auto rounded bg-card p-3 text-xs text-muted-foreground border border-border">
            {this.state.error?.message}
          </pre>
          <button
            onClick={() => window.location.reload()}
            className="mt-4 rounded bg-primary px-3 py-1.5 text-xs text-primary-foreground font-medium"
          >
            Reload Window
          </button>
        </div>
      );
    }
    return this.props.children;
  }
}
```

## 9. Conclusion

The Ferryx codebase demonstrates strong defensive foundations:
* Strict Git repository root canonicalization and argument validation preventing path escaping and flag injection.
* POSIX `0700`/`0600` socket and state file permissions.
* Clean separation of frontend local tab IDs from native backend PTY session IDs with automatic crash recovery.
* High-entropy 64-character bearer tokens and process-group signaling.

Addressing the critical and high-severity items highlighted above—specifically adding canonicalization to static asset serving (`SEC-01`), rate-limiting pairing code exchanges (`SEC-02`), restricting child webview navigation events (`SEC-04`), bounding daemon read buffers (`SEC-05`), and adding a top-level React Error Boundary (`SEC-07`)—will elevate the system to production-grade security and robustness.
