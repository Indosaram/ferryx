Done. Sidebar now renders a project-nested tree with per-project accordion state.

**What changed in `Sidebar.tsx`:**
- Expansion is no longer derived from `activeProjectId`. It's driven by `collapsedProjects: Set<string>`, persisted to `rorca.sidebar.collapsedProjects` as a JSON string array. If nothing is persisted, projects other than the active one seed collapsed; once anything is persisted, the stored set is authoritative so a user-opened non-active project survives a remount. Projects registered after mount inherit the same default.
- Each project row is now a two-button row: a dedicated chevron toggle (`aria-expanded`, `aria-label="Expand|Collapse <id>"`) that only opens/closes, and the project label button that only selects (`aria-current` marks the active project). Toggling one project cannot affect another or change selection.
- Worktrees are grouped per project via `groupWorktreesByProject`: branch identity `orca/<wsId>/<slug>` routes a worktree to its owning registered project; anything unattributed falls back to the active project (the only project whose worktrees the store actually holds). Each expanded project renders its own `WorktreeList` indented under it with the existing `border-l` tree rails, labeled `<project> worktrees`, and wired to the same select/create/refresh/delete handlers. `activePath` is only passed to the active project's group so a non-active project can't show a false current row.

**Tests** (`Sidebar.test.tsx`): updated the existing nesting/selection tests for the split toggle/label buttons, and added coverage for independent open/close of `default` vs `rorca-qa` in both directions, toggle-does-not-select, localStorage persistence across remount, branch-based worktree routing between groups, per-group refresh/delete/create wiring, and the empty-project "create the first worktree" path.
