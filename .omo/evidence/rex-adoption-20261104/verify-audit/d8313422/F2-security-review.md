## Blocking findings

### R2-1 HIGH: consent approves a freshly reloaded manifest, not the identity the owner reviewed

Evidence chain:
- `ui/src/components/settings/PluginsSection.tsx:15,19-21,29-37` displays discovery-time module/digest/capabilities, but enable submits only `{name, enabled}`.
- `src-tauri/src/ipc/layout.rs:24-31` forwards only that name/bool; `protocol.rs` PluginSetEnabled likewise has no expected manifest identity.
- `src-tauri/src/daemon/plugins/registry.rs:63-79` reloads whatever manifest now occupies that name, hashes its selected module, and persists it as approved without comparing to the displayed identity.

A manifest can change between discovery/render and the click (or while the enable request is pending). An owner reviewing a render-only digest A can unknowingly approve digest B with `write`/`listSessions`. Existing grants are namespaced only by `plugin:<name>`, so a changed module can immediately reuse any prior grants for that name once the unseen new capability is approved. The digest check is internally correct but proves integrity of the newly read object, not informed consent. File replacement after the digest snapshot is correctly handled by passing the exact byte vector; this separate consent race is not fixed by that protection.

Bounded repair: send the complete reviewed manifest or canonical manifest fingerprint with enable; under the consent lock compare to the current parsed manifest and reject mismatch as approval-required. Hash and launch the bytes matching that approved object. Keep disable possible by name. Add a deterministic discovery(A) -> replace(B) -> enable(expected A) negative test and unchanged-A positive test, through IPC/registry rather than only Approvals::enabled.

### R2-2 HIGH availability: render-only guest can exhaust the daemon heap outside its Wasmi memory budget

`plugins/registry.rs:18,24` stores all view documents in an unbounded BTreeMap. `server.rs:6812-6816` inserts a document at each guest-selected `(name, view)` without limiting view count or aggregate bytes. `plugins/mod.rs:126-127` authorizes any view name for a render-capable plugin. MAX_LINE bounds one message, not total retained state.

The actual runner permits 32 host calls per tick for 3600 ticks (`plugins/runner.rs:45-46,87-95`). A module with one memory can reuse the same roughly 60 KiB HTML payload and vary view names; 115200 requests retain roughly 6.6 GiB in the **daemon**, not the bounded runner. Four lifetime/restart attempts can increase this further because `runtime.rs:104-118` restarts after exit and only Registry::stop clears views (`registry.rs:125`); requests targeting views never attached to a pane are still retained. This needs no write grant, ambient syscall, or Wasmi escape. At normal 32 requests/second it is a practical process-wide memory-growth path, not an unbounded-loop speculation.

Bounded repair: enforce per-plugin view cardinality plus aggregate stored-document bytes in daemon dispatch before insertion, with replacement accounting and an error on overflow; bound global aggregate or enabled-plugin count as well. Clear obsolete views on exhausted/restarted runtime as policy requires. Test using the real bridge with distinct view keys: limit+1 refused, existing state/budget unchanged, replacing an existing view allowed within budget, disable frees accounting. A per-frame size cap alone is insufficient.

## Actual Wasmi boundary inspection

- **Runner entry:** CLI main and desktop main invoke runner::entry before ordinary initialization. Runtime uses the same trusted executable, not a manifest-specified binary, and no shell or guest-controlled argv.
- **Imports/exports/start:** runner.rs:31-43 constructs a fresh Engine/Store/Linker. The only func_wrap is ferryx.request (:44); no WASI or ambient filesystem/network/process/environment linker is installed. Unknown imports fail instantiate before start; guest start is permitted (:84-85) and uses the same initial fuel/call counter/import policy. Export `tick` is type-checked as `(i64)->()` after start (:86); request resolves an exported memory or traps (:57-58). A module without a matching tick may run its authorized start function before being rejected; those start effects are still checked by daemon authorize, so this is not extra authority.
- **Budgets:** binary module snapshot capped at 1 MiB before interpreter; store memory 8 MiB, table elements 1024, one instance/memory/table; fuel 5 million for start and each tick; 32 requests each tick; 5-second dispatch timeout; 6-second guest reply timeout; 3605-second outer process lifetime. Module validation/translation occurs before store resource limits/fuel, but is inside the out-of-process lifetime cap. No claim total interpreter RSS equals 8 MiB. Wasmi stack defaults are not an application-configured process RSS limit. Daemon render accumulation escapes these otherwise meaningful guest controls (R2-2).
- **Pointer arithmetic:** negative i32 pointers/lengths/capacity rejected via try_from, per-span MAX_LINE enforced, checked_add prevents wrap; memory.read checks input extent and explicit output end check precedes stdout side effect. Input/output aliasing is safe because request is copied to a Vec before dispatch; response size is checked before memory.write. Insufficient response capacity can fail after a permitted host effect and is not rollback; sequential request semantics must not promise transactional retry.
- **Dispatch:** only ListSessions/GetCapabilities/Write/PluginRender match the explicit allowlist; manifest capability required; Write must pass live pane grants as plugin:name with no workspace/own-session exemption and plugin:-prefixed targets denied. Public PluginRender rejects because it needs bound stdio identity. Render closure captures plugin name, not a guest-selected plugin identity. Revocation affects the next authorization, not an already-authorized in-flight write.
- **Approval/TOCTOU:** complete manifest equality binds saved module path, digest, version and capabilities. approved_bytes reads capped bytes, checks magic and SHA256, returns exactly that snapshot for stdin on each attempt. Path/symlink/content changes after read cannot substitute launched bytes. Discovery-to-approval identity is the unresolved race above. Legacy approvals are not promoted to Wasm approvals. Malformed manifests otherwise fail closed.
- **EOF/disable/teardown:** stdin reader exits runner on EOF/malformed response; request waits bounded time. An idle/computing guest cannot spawn descendants via imports. Runtime cancellation selects stop against the serve future and lifetime timer, kills and awaits the direct child; kill_on_drop covers future cancellation but is not a substitute for explicit wait. Registry stop awaits supervisors, removes view entries; handover CommitHandover stops all before recording transfer, successor restores approval snapshot before startup. Idle restart likewise stops before checkpoint/restart. No independently executed native teardown or EOF result is claimed; tests inspected include real Wasm render bridge and disable/reap, but lack complete adversarial EOF/start/approval-race/aggregate-state coverage.
- **Inherited handles:** env_clear removes tokens/config via environment, stdio is explicitly piped/null, and Windows pipe security attributes are noninheritable. Runtime does not explicitly enumerate/close every inherited Unix FD or Windows handle. This is not asserted as an OS sandbox: no guest import can enumerate/use those ambient resources. An interpreter/native host compromise would have runner OS authority; defense-in-depth handle hygiene does not substitute for the import boundary. Platform automatic execution evidence is still required.
- **Render boundary:** unchanged PluginPane.tsx:29-31 uses srcDoc plus empty sandbox and no-referrer, no allow-scripts/same-origin/forms/popups/top-navigation. block_document (:144-149) prepends CSP default-src none with only plugin image/style sources, base/form none. Untrusted HTML never enters the parent DOM. This is plausible opaque-origin scriptless isolation, not a native-child-webview implementation or executed security proof. Wasmi does not make rendered HTML trusted. Native Linux/Windows isolation/CSP/API negatives and automatic checks remain owed; macOS manual/GUI waiver is recorded without inventing missing proof or renewing the waived manual work. Plugin-origin resource serving remains absent.
