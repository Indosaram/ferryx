## Known limitations / follow-ups

- **No MSI**: WiX enforces `ProductVersion` major ≤ 255; CalVer `2026.905.1` (major 2026) can never produce an MSI. This is why no local release since v2026.08.30.1 has shipped one. The landing page (`site/src/lib/downloads.ts`) still links `Ferryx_x64.msi` — that button will 404 until the MSI card is removed from the site (suggested follow-up).
- **MSI build env**: `TAURI_SIGNING_PRIVATE_KEY` on Windows must contain the key **content** (base64 string), not a file path — path form silently produces no `.sig`.
- Main-tree `src-tauri/target` (162 GB of stale build cache) was deleted during this session to unblock the disk-full macOS build; 160 GB free afterwards.

## Tooling gotchas hit (recorded for next time)

- ssh → Windows PowerShell: `Start-Process powershell -ArgumentList …` loses its arguments in ssh sessions (spawned a bare powershell). Use `Invoke-CimMethod Win32_Process Create` for detached launches.
- Bash scripts generated in JS template literals: `{ …; exit 1 }` missing `;` before `}` is a syntax error bash reports as "unexpected end of file" at EOF. Always `bash -n` locally before scp.
- Multi-file `scp` reported success while the target name mismatch (`resume-0905.ps1` vs `resume-0905-win.ps1`) caused a 0-byte phantom file — verify sizes after transfer when the name is derived.
- `gh release create` with 16 assets took ~8 minutes on this uplink; the release object appears only after asset uploads complete.
