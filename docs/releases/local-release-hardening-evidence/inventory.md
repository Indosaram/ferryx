# Ferryx Local-Release Hardening Evidence: Receipt-Driven Release Assembly

**Date:** 2026-09-08  
**Scope:** Production hardening and verification proof for `scripts/build-latest-json.mjs`, `scripts/build-latest-json.test.mjs`, `scripts/lib/release-contract.mjs`, and `scripts/release-contract.test.mjs`.  
**Architecture Boundary:** Host Coordinator release assembly (`Wave 2 — Artifact Verification & Manifest`). Compatible with Node.js >= 22.22 and Bun >= 1.4. Zero external npm dependencies.

---

## 1. Executive Summary

The legacy permissive directory-scanning release manifest generator (`scripts/build-latest-json.mjs`) has been replaced by a fail-closed, receipt-driven release assembly engine. 

Under the old architecture, release manifests were generated by loosely globbing updater files in a directory, guessing platform targets from filename patterns, skipping unsigned binaries with a warning, and allowing unverified or partial releases to publish.

The hardened release assembly engine enforces:
1. **Receipt-Driven DAG Closure:** Exactly three host receipts are required (`macbook`, `omaki`, `maho-win`), matching the release plan's `runId`, `commitSha`, and `appVersion`, with `exitCode == 0`.
2. **Strict Schema Validation & Unknown Property Rejection:** Both `release-plan.json` and `build-receipt-<host>.json` enforce `schemaVersion: 1`, reject fake hosted schema URLs (`$schema`), and reject unexpected or credential fields.
3. **Canonical Version Identity:** Release plan tags (`vYYYY.MM.DD[.R]`) are strictly validated against calendar rules (year >= 2026, month 1..12, valid days per month accounting for leap years), and monotonic mappings to App SemVer (`toAppVersion`) and MSIX Quad (`toMsixVersion`) are enforced.
4. **Host & Kind Invariant Bindings:** Artifact kinds are strictly bound to authorized builder hosts:
   - `macbook`: `macos-updater` (`.app.tar.gz`) and `dmg` (`.dmg`)
   - `omaki`: `appimage` (`.AppImage`, `.AppImage.tar.gz`) and `deb` (`.deb`)
   - `maho-win`: `msix` (`.msix`), plus `nsis` (`-setup.exe`, `.nsis.zip`) iff `channels.nsisMigration == true`.
5. **Real Cryptographic Verification:** All updater artifacts (`macos-updater`, `appimage`, `nsis`) must pass Minisign Ed25519 signature verification (Blake2b-512 prehash `ED` format or raw `Ed`) including trusted comment signature validation via `scripts/lib/minisign-verify.mjs` against the configured updater public key.
6. **macOS Archive Layout Integrity:** All `macos-updater` `.app.tar.gz` payloads are verified before publication using `scripts/assert-updater-archive-layout.mjs`, ensuring entries are rooted in `Ferryx.app/` with zero AppleDouble (`._*`) corruption.
7. **Post-Copy Staged Artifact Checksum Verification:** Artifact hashes are validated not only before copy, but re-verified immediately after staging into the temporary directory to guarantee zero TOCTOU data tampering or filesystem corruption across the copy boundary.
8. **Filesystem Jail & Safe Relative Paths:** Safe relative path syntax is enforced. Real filesystem verification confirms exact byte sizes and SHA256 hashes against receipts, backed by a `realpath` jail preventing symlink escapes or directory traversal beyond `artifactsDir`.
9. **Deterministic Stable Aliases:** Exact inventory payloads and signatures are published alongside canonical stable aliases (`Ferryx_universal.dmg`, `Ferryx_amd64.AppImage`, `Ferryx_amd64.deb`, `Ferryx_x64.msix`, and `Ferryx_x64-setup.exe` if migration).
10. **Checksum Closure & Atomic Publication:** `latest.json` is generated first with `pub_date` derived from `plan.sourceDateEpoch`. `SHA256SUMS.txt` is computed across all publish files (including `latest.json`). Assembly stages into a unique sibling temporary directory and atomically renames only upon 100% verification. Pre-existing `outDir` is rejected, and any verification failure aborts leaving zero partial or publishable output.
11. **Legacy CLI Deprecation:** Invocations using legacy permissive CLI parameters (`--version`, `--dir`, `--repo`, `--tag`, `--out`) fail immediately with exit code 2 and explicit migration guidance.

## 2. Technical Architecture & Security Controls

### 2.1 Release Plan Specification (`release-plan.json`)

The release plan is credential-free, reproducible, and machine-verifiable:
- `schemaVersion`: Strictly integer `1`.
- `runId`: Non-empty release execution identifier (e.g. `rel-20260908-1`).
- `repo`: Repository owner/name (e.g. `Indosaram/ferryx`).
- `commitSha`: 40-character lowercase hexadecimal Git commit hash.
- `tag`: Release tag formatted `vYYYY.MM.DD[.R]`.
- `appVersion`: App SemVer matching `toAppVersion(tag)`.
- `msixVersion`: Windows Store Quad version matching `toMsixVersion(tag)`.
- `channels`: `{ store: boolean, nsisMigration: boolean }`.
- `requiredTargets`: Validated target platform array:
  - If `nsisMigration == false`: strictly `["darwin-aarch64", "darwin-x86_64", "linux-x86_64"]`.
  - If `nsisMigration == true`: strictly `["darwin-aarch64", "darwin-x86_64", "linux-x86_64", "windows-x86_64"]`.
- `toolchains`: `{ node: string, bun: string, zig: string, rust?: string, tauri?: string }`.
- `sourceDateEpoch`: Integer Git commit timestamp.
- `createdAt`: ISO 8601 creation timestamp.

### 2.2 Host Build Receipt Specification (`build-receipt-<host>.json`)

Produced by each platform builder and gathered into `receiptsDir`:
- `schemaVersion`: Strictly integer `1`.
- `runId`: Bound to `plan.runId`.
- `host`: Strictly one of `macbook | omaki | maho-win`.
- `commitSha`: Bound to `plan.commitSha`.
- `appVersion`: Bound to `plan.appVersion`.
- `completedAt`: ISO 8601 timestamp.
- `exitCode`: Strictly integer `0`.
- `toolchains` *(optional)*: Strict provenance object containing observed builder toolchain versions (`node`, `bun`, `zig`, `rust`, `tauri`). Unknown or credential-like keys are strictly rejected.
- `artifacts`: Array of artifact entries:
  - `kind`: Strictly one of `macos-updater | dmg | appimage | deb | msix | nsis`.
  - `name`: Artifact filename without directory separators.
  - `relPath`: Safe relative path within `artifactsDir`.
  - `bytes`: Positive integer byte size matching on-disk file size.
  - `sha256`: 64-character lowercase hexadecimal hash matching on-disk SHA256.
  - `signatureRelPath`: Safe relative path to `.sig` file (mandatory for updater kinds; null or safe relative path for standalone installers).
  - `targets`: Updater target platform strings (empty for standalone installers; validated against kind definitions).

### 2.3 Strict Host-to-Kind Matrix

| Host | Permitted Artifact Kinds | Is Updater | Expected Targets | Stable Alias |
|---|---|---|---|---|
| `macbook` | `macos-updater` | Yes | `darwin-aarch64`, `darwin-x86_64` | `Ferryx_universal.app.tar.gz` |
| `macbook` | `dmg` | No | `[]` | `Ferryx_universal.dmg` |
| `omaki` | `appimage` | Yes | `linux-x86_64` | `Ferryx_amd64.AppImage` |
| `omaki` | `deb` | No | `[]` | `Ferryx_amd64.deb` |
| `maho-win` | `msix` | No | `[]` | `Ferryx_x64.msix` |
| `maho-win` | `nsis` (if migration) | Yes | `windows-x86_64` | `Ferryx_x64-setup.exe` |

### 2.4 Cryptographic Verification Engine
All updater payload signatures are verified using `verifyMinisign` from `scripts/lib/minisign-verify.mjs`:
- Verifies 8-byte key ID equality between public key and signature.
- Verifies Ed25519 payload signature against Blake2b-512 prehash of artifact data.
- Verifies Ed25519 global signature over `payloadSig || trustedComment`.
- Fails closed if any updater signature is missing, invalid, or forged.

### 2.5 macOS Updater Archive Layout Verification
All macOS updater archives (`.app.tar.gz`) are verified prior to publication using `scripts/assert-updater-archive-layout.mjs`:
- Ensures the payload is a valid gzip archive containing a standard tarball.
- Enforces root path restriction: every payload entry must be rooted inside `Ferryx.app/`.
- Rejects archive containing AppleDouble metadata entries (`._*`) to avoid Tauri updater extraction aborts.

### 2.6 Realpath Jail & Path Traversal Prevention
Every relative path (`relPath` and `signatureRelPath`) is verified:
1. Syntax check: Rejects absolute paths, null bytes, and path components containing `..` or `.`.
2. Resolution & Existence check: Confirms target file exists.
3. Inode & Symlink check: Inspects `realpathSync(fullPath)` to confirm the canonical path resides strictly under `realpathSync(artifactsDir) + path.sep`. Symlinks escaping the artifacts tree are rejected.
4. Regular file check: Confirms `statSync(fullPath).isFile()` is true.

### 2.7 Atomic Output Staging & Post-Copy Verification
1. Rejects assembly if target `outDir` already exists.
2. Allocates isolated sibling temporary staging directory `.staging-<basename>-<randomHex>`.
3. Generates and writes `latest.json` FIRST.
4. Stages all verified artifacts, signatures, and stable aliases.
5. **Post-Copy Checksum Guard:** Immediately after copying each artifact (and stable alias) into the staging directory, computes the SHA256 of the staged destination file on disk and verifies equality against `artifact.sha256`. Fails closed if any mismatch is detected.
6. Hashes all staged publish files (including `latest.json`, excluding `SHA256SUMS.txt`) and writes `SHA256SUMS.txt`.
7. Atomically renames staging directory to destination `outDir`.
8. If any error occurs at any stage, the temporary staging directory is cleaned up in a `finally` block, leaving zero publishable or partial output.

```javascript
// Programmatic API:
export function assembleRelease(options: {
  planPath: string,
  receiptsDir: string,
  artifactsDir: string,
  outDir: string,
  publicKey?: string,

  outDir: string,
  plan: object,
  receipts: object[],
  manifest: object,
  files: string[],
```

```bash

  --artifacts-dir release-run/<runId>/artifacts \
  --out-dir release-run/<runId>/publish \
```
