## SHARED-NATIVE-01: native menu listeners lack popup correlation

**Confirmed source/API-contract defect, conditional user manifestation; new ID, not an alias of an existing accepted menu finding.** Provisional owner should extend the existing UI/native owner only after lead allocation of nativeMenu and backend menu seam; no ownership change is made here.

`nativeMenu.ts:54-60` dispatches every global menu-action ID to its callback, then always removes that listener. Neither requested entries nor popup identity are checked. Backend `native_menu.rs:251-260` sends only id. Cleanup on dismissal waits 200ms after invoke (`:68-71`). Worktree/project rows each hold independent refs; dismissing A does not synchronously clear its listener, and opening B clears only B's prior ref. A B selection arriving while A's dismissal timer is pending therefore invokes both callbacks. Shared `copy-path`/`reveal` IDs can act on A's captured path as well as B's. Same-ID row menus show why filtering merely by allowed item IDs is insufficient. If the action ID is unrelated, it still consumes A's listener. This is not proof of destructive deletion bypass: the identified concrete cross-row action is copy/reveal; permission/confirmation downstream was not audited.

There is a second lifetime boundary within this same ownership mechanism: callers receive the disposer only after invoke completes (`TabBar:128-130`, row:121-124, project:661-664). Unmount/reopen while listen/invoke is pending cannot cancel through the still-null ref; late completion can publish an obsolete disposer. Exact occurrence through native user input remains unexecuted. Prefer explicit per-popup ownership and completion/settlement rather than a bigger grace delay; an arbitrary global event must not reach an obsolete callback.

## SHARED-NATIVE-02: startup focus snapshot precedes subscription

**Confirmed source ordering defect with reachable Windows attention consumers; manifestation conditional on startup focus transition.** This is not native-input-03 (the backend global mouse monitor) and not a claimed permanent terminal-input failure.

`nativeWindowFocus.ts:14-15` awaits isFocused before even calling onFocusChanged. Installed API `window.js:474-478` implements snapshot as invoke; `:1724-1735` then separately registers focus and blur listeners, without replay/snapshot reconciliation. Reachable ordering: app starts while focused; backend answers true; user switches to another window before blur registration; no listener captures that blur; cached true persists until another native event. A real agent attention/bell event then sees true through App653/662 or workspaceStore341, rather than falling back to DOM state, and can be acknowledged/suppressed despite the app being backgrounded. The reverse startup transition can retain false and create unwanted background treatment. This does not require an invented caller; App starts this singleton and real notification/store code reads it.

Recommended narrow correction is subscription-before-snapshot with event revision protection so an older outstanding snapshot cannot overwrite a newer event. Merely swapping statements without snapshot/event arbitration creates a different stale-write possibility. Failure-to-register and retry policy remain explicit design/error cases, not speculative Windows API outages.

Proposed exact regression: `bun run --cwd ui test src/lib/nativeWindowFocus.test.ts src/lib/notificationCoordinator.test.ts`. Add isolated module instances, exact registration and snapshot deferreds, register signals before start, and model a focus change during setup plus an event while snapshot is unresolved. Require final getter equals newest state and one real coordinator bell/attention decision follows that value (mock native dispatch, not the getter/coordinator decision). A model where missed events are magically replayed is invalid. No sleeps or polling; bounded test timeout only detects missing completion. Add positive focus custom-event, false-focus no custom-event, duplicate start and setup rejection/null fallback cases; reset module/mocks and remove DOM listeners in finally.

Real Windows acceptance: owned startup/debug focus gate, foreground snapshot then Alt+Tab before subscription completion, explicit ready signal, owned terminal bell/attention event. Background event must produce unread/notification decision rather than seen; latest focused control must not produce background unread.
