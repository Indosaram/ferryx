## Confirmed missing-coverage findings

### GT-01 - Harness ownership proof and teardown success are incomplete

- Bridge survival reads endpoint.pid and only tests truthiness at `scripts/qa/ssh-bridge-survival.mjs:205-207`; reapPid at 50-89 signals numeric PIDs, treats some probe errors as return, polls, and merely warns on failure. Finally at 376-409 catches cleanup errors and removes the fixture regardless. It can signal a recycled PID even after successful pty.stop, and prints cleanup fields without proving removal/reaping succeeded.
- Setup repeats endpoint-PID-only trust at `scripts/qa/ssh-helper-setup.mjs:265-279`; cleanup at 382-421 logs failures from reapPid/reapChild yet calls rmRetry anyway. The comment that every disappearance is verified is false. `FERRYX_QA_SSH_TARGET` can name another host while endpoint reading and process.kill remain local; there is no same-host/process-namespace proof.
- Direct helper survival uses owned Child handles and an epoch-scoped TargetRef, which is materially safer. However `scripts/qa/ssh-helper-survival.mjs:292-335` removes the root before checking remainingLivePids; cleanup errors set exitCode but do not retain the fixture. Its endpoint is not compared against the daemon Child PID before destructive RPC. Numeric process existence is not process identity.
- Process survival uses a private canonical root/owner sentinel and explicit runtime/data/home, and its example checks those at `src-tauri/examples/ssh_process_survival_qa.rs:7-13`. It only signals Child handles and retains roots on cleanup failure (`scripts/qa/ssh-process-survival.mjs:184-202`): do NOT equate it with shared-root DS-10. Nonetheless every connect opens the path without handshake at 51-57, and line 137 sends Shutdown without endpoint PID == daemon.pid. Production handshake supplies pid/binary/epoch (`src-tauri/src/daemon/server.rs:1553-1567`), and Shutdown exits the receiver process at 2140-2143. Owner filename plus readiness does not prove the current socket peer identity.
- Resume-CWD has a private root and direct Bun child handle, not a shared default socket. Its handshake at `scripts/qa/verify-ferryx-resume-cwd.mjs:86` checks only type, ignoring PID/binary; cleanup closes sessions then removes root at 129-145 without a complete descendant/receiver-close receipt. Its child env explicitly sets HOME/USERPROFILE/runtime/session but not FERRYX_DATA_DIR; audit the effective Bun environment before claiming inherited data isolation. Server persistent-lock resolution gives FERRYX_DATA_DIR priority (`src-tauri/src/daemon/server.rs:270-293`). No actual profile contamination is claimed.
- Required gate: owned root + restricted ACL/mode + authenticated endpoint + expected binary/PID/start identity before any Shutdown/session deletion; maintain a process handle where possible. Detached helper PID must be tied to owned executable/root/start identity, not endpoint text alone. Re-prove after reconnect. If proof or reap fails, return nonzero and retain owned fixture; never kill by process name, stale PID, ancestor sweep or fallback user endpoint. Related safety principle: P19/P22, but these are separate files, not duplicate defects.

Their ConPTY cursor-report handling is source only; direct survival additionally requires initial ESC[6n at `scripts/qa/ssh-helper-survival.mjs:148-162`, which must be validated on the target build rather than assumed universal. Existing read RPC is condition-variable/event-backed, not a fixed sleep; do not relabel every waitMs as timing luck.
