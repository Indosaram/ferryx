## IMAGES-GAP-01 - accepted raw RGB image aborts the entire render snapshot

**CONFIRMED shared source defect, applicable to Windows; no observed runtime RED.** New unique mechanism, not RF-06 or the owner's already-repaired PNG/device-dimension mismatch.

- Upstream acceptance: pinned `src-tauri/vendor/ghostty/src/terminal/kitty/graphics_image.zig:510-554` accepts nonzero raw RGB dimensions up to10000 with exact width*height*3 bytes. `graphics_storage.zig:270-280` charges actual stored bytes against the64 MiB limit set at `lifecycle.rs:43-54`. A4097x4097 RGB payload is50,356,227 bytes, below67,108,864; its16,785,409 pixels exceed IMAGE_LIMIT/4=16,777,216. It is a valid accepted inline image, not malformed PNG or unavailable GPU prerequisite.
- Failure: `images.rs:154-169` rejects pixels>IMAGE_LIMIT/4 before RGBA conversion, returning InvalidValue. It does this before checking viewport visibility at202-207. `terminal.rs:479-483` propagates capture failure instead of returning the text snapshot. `surface_host.rs:702-749` and native target2553-2657 carry the fallible snapshot/render chain; renderer's skip-oversize check at `renderer/images.rs:53-59` is never reached. Subsequent text frames continue failing while that placement remains in the iterated state.
- Minimal repair recommendation: keep the RGBA allocation bound but omit unsupported expanded-size images from the native image snapshot while retaining usable text and supported placements, or reject these transmissions at the protocol boundary before acceptance. Do not raise memory limits or add tiling as this repair. Distinguish invalid foreign buffer ABI from a supported input exceeding the renderer's own capacity.
- **Exact future regression invocation** after allocating a new case in the existing target: `cargo test --manifest-path src-tauri/Cargo.toml --features native-terminal --test native_terminal_images kitty_rgb_expansion_limit_does_not_block_text_frames -- --exact --nocapture`. This case does not exist yet and was not run. Feed the real parser4097x4097 RGB in deterministic protocol chunks, confirm accepted query/status through machine bytes, then write a green-background cell outside its one-cell placement. RED is render_snapshot InvalidValue/no frame; GREEN is successful snapshot/readback with that exact green cell and no unsupported image painting. Preserve a smaller valid RGB placement and assert its pixels too. No manually forged snapshot or all-images-empty mock can establish this chain.
- **Current Windows binary failure/success condition:** in an explicitly owned debug terminal feed the same inline stream and following text; before fix no new text frame is presented, after fix the new text cell is presented and the supported image survives. Record exact debug exe/library/source/target hashes and a presentation-completion signal/readback or native capture. Receive/subscribe before trigger, use bounded failure deadline, never sleep/poll for green. Close/reap only the owned terminal, no daemon replacement.
