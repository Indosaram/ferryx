## Part 2 - live HTTP endpoint contract

A loopback HTTP server serves the manifest that `scripts/build-latest-json.mjs` generated from the
real signed fixture, and the harness walks the whole updater path: GET the manifest, compare the
installed version against the manifest version, download the artifact the manifest points at, and
verify its signature with the public key committed in `src-tauri/tauri.conf.json`. The final step
re-verifies a tampered copy of the same download, which must fail.

Manifest generated by:
```
$ node scripts/build-latest-json.mjs --version 2026.08.26.1 --dir <release-dist> \
    --out <release-dist>/latest.json --repo Indosaram/ferryx --tag v2026.08.26.1
platforms=darwin-aarch64,darwin-x86_64

generator was run against the actual `Ferryx.app.tar.gz` and its matching `.sig`, not a fixture:

```
$ node scripts/build-latest-json.mjs --version 2026.826.1 --dir <final-bundle-staging> \
