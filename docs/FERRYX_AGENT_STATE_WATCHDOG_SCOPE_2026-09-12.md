# Ferryx 에이전트 상태 워치독 — 구현 범위 확정서

**작성:** 2026-09-12 · **상태:** 범위 확정, 착수 대기 · **실행표 ④번**

세션은 살아 있는데 안에서 돌던 에이전트만 끝난 경우, 탭·워크트리의 활동 표시가 마지막 상태(대개 Working)에 무기한 붙들린다. 이 확정서는 그 구멍만 막는다.

---

## 1. 반드시 지켜야 할 불변식 (설계를 결정함)

상태는 익스텐션 보고가 아니라 **화면 판독**으로 결정된다. `src-tauri/src/native_terminal/surface_host.rs:574`가 렌더 스냅샷의 행 텍스트와 타이틀을 `agent_detect::default_engine()`에 넣고, 11개 매니페스트(claude·codex·omo·opencode·cursor·gjc 등) 규칙을 전역 평가해 최상위 우선순위 매치를 채택한다.

매치가 없으면 `agent_detect/engine.rs:90`이 **이전 상태를 HOLD**한다. 이것은 버그가 아니라 의도된 불변식이며 테스트 이름이 그 의도를 못박고 있다: `"absence of evidence must hold, never reset"`.

따라서 **시간 기반 타임아웃 강등은 금지한다.** 조용히 오래 생각하는 에이전트를 완료로 오판하기 때문이다. 초안의 "주기적 조정 패스"는 이 이유로 철회됐다.

## 2. 이미 처리되는 것

세션 자체가 사라지는 경우는 이미 정리된다 — `src-tauri/src/daemon/server.rs:1792`·`:2657`·`:2695`가 `agent_states.remove(session_id)`를 호출한다.

## 3. 남은 구멍 (이번 작업 대상)

**세션은 살아 있고 에이전트 프로세스만 종료된 경우.** 셸 프롬프트로 돌아오면 어느 매니페스트도 매치하지 않아 HOLD가 마지막 상태를 영구히 유지한다. 게다가 감지는 출력이 있을 때만 도는 트레일링 방식이라, 새 출력이 없으면 재평가 자체가 일어나지 않는다.

## 4. 확정된 해법

- **A. 프로세스 증거 기반 해제.** PTY의 foreground 프로세스가 에이전트에서 셸로 돌아왔다는 사실은 "증거 없음"이 아니라 **종료의 적극적 증거**다. 이 전이가 관측될 때만 활동 상태를 해제한다. HOLD 불변식과 충돌하지 않는다 — HOLD는 매치 실패 시의 규칙이고, 이것은 별개의 긍정적 신호다.
- **B. 수동 초기화.** 탭/워크트리 컨텍스트 메뉴에 "상태 초기화" 액션 하나. 어떤 자동 판정도 실패할 수 있으므로 사용자 탈출구를 항상 남긴다.
- **C. 해제 사유 로깅.** 어떤 신호로 해제됐는지 기록해 추후 유령 상태 조사를 가능하게 한다.

## 6. 테스트

- 에이전트 → 셸 전이에서 상태가 해제된다
- 조용한 에이전트(출력 없음, 프로세스 생존)는 **해제되지 않는다** — HOLD 불변식 회귀 방지
- 수동 초기화가 상태를 지우고 다음 실제 전이가 정상 복구된다
- 기존 `"absence of evidence must hold, never reset"` 테스트가 계속 통과한다
