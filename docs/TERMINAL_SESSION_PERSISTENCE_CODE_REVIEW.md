# Ferryx Terminal Session Persistence — Code Review

## Executive verdict

The implementation gets the most important architectural decision right: the standalone daemon is the production PTY owner, the GUI is wired around `DaemonClient`, protocol v2 has per-session sequencing and subscriber-before-snapshot attach, and the production path does not silently fall back to a GUI-owned PTY. However, the implementation does **not yet satisfy the specification's completion criteria**. There are still correctness failures at the boundaries that matter most during reconnect/backpressure/failure: runtime replay-gap information is discarded before the renderer can react, generic daemon request retry can duplicate terminal input, the Tauri spawn boundary does not preserve a caller-stable `clientRequestId`, restore can convert daemon-query failures into false "session exited" state, remote terminal streaming silently drops lagged output, PTY close can wait indefinitely, and the GUI client connects to an existing UDS before enforcing the section-9 ownership/symlink checks. The implementation is therefore **PARTIAL, overall grade C+**: the foundation is credible, but the losslessness, recovery, and failure semantics are not yet strong enough to call terminal persistence fundamentally solved.

## Findings matrix

### Critical

No Critical finding was identified. The daemon remains the PTY owner and there is no production direct-PTY fallback; the highest-risk defects are loss/retry/recovery semantics rather than an architectural reversion.

## Test-coverage gaps against sections 11–12

1. **No simultaneous multi-client attach contract.** The standalone persistence test drops Client A before Client B reconnects (`src-tauri/tests/daemon_persistence_contract.rs:531-818`); it does not keep two independent clients attached concurrently while output is generated and verify both receive the same ordered sequence without interference. Add a test with two dedicated attach sockets plus a separate control connection, and prove neither attachment monopolizes control traffic.

2. **No standalone forced ReplayGap / `Lagged` E2E.** `test_daemon_output_sequence_contiguity_and_replay_gap` verifies monotonic output and an attach at the current end sequence, but it never forces ring eviction and never asserts `gap.is_some()` (`src-tauri/tests/daemon_persistence_contract.rs:873-961`). There is server-unit coverage for lag replay (`src-tauri/src/daemon/server.rs:1269-1310`), but the important daemon socket → client → Tauri pump → renderer reset path remains untested.

3. **No Tauri/UI runtime-gap propagation test.** Existing UI tests cover initial attach sequence/epoch behavior and HMR retention, but the Rust pump currently discards `Gap`, so there is no test that injects a daemon `Lagged`/gap frame and proves the renderer resets before replay (`src-tauri/src/ipc/terminal.rs:148-166`, `ui/src/lib/terminalOutputScheduler.ts:109-160`). This missing test is directly responsible for H-01 escaping.

4. **No real launchd bootstrap/bootout integration contract.** The standalone file tests plist content/path and missing-uninstall idempotency only (`src-tauri/tests/daemon_persistence_contract.rs:1032-1067`). It does not install into the user launchd domain, verify daemon startup/KeepAlive, inspect status, then bootout and verify cleanup.

5. **No executable GUI-SIGKILL → relaunch E2E.** The persistence contract simulates client loss by dropping sockets and separately kills the daemon in the headless CLI test; it does not spawn a real GUI-role process, SIGKILL only that process, verify daemon/shell PID survival, and relaunch/reconcile (`src-tauri/tests/daemon_persistence_contract.rs:452-529`, `src-tauri/tests/daemon_persistence_contract.rs:531-818`).

6. **No actual Vite HMR / webview full-reload E2E.** The unit-level HMR contract does correctly assert `spawnTerminal` and `closeTerminal` are not called (`ui/src/state/workspaceStore.hmrRetention.test.tsx:353-354`), but section 11 calls for a real HMR with a long-running output producer and sequence continuity, plus a full reload replay check.

7. **No dynamic-CWD completion test.** There is no contract that runs `cd`, proves daemon `DescribeSession` observes the new working directory, restarts/reloads the GUI, and verifies the persisted/restored CWD matches the live shell. Current implementation evidence shows it cannot pass (`src-tauri/src/daemon/server.rs:789-801`, `src-tauri/src/ipc/terminal.rs:560-574`).

8. **No ambiguous-response retry test for mutating daemon requests.** There is no test that applies a `Write`, drops the response/connection after server-side application, and verifies the client does not send the input twice. This should be added before changing retry semantics (`src-tauri/src/daemon/client.rs:276-291`).

9. **Client-side UDS trust is not integration-tested.** Server unit tests exercise symlink/runtime-dir defenses, but there is no `DaemonClient` test that places a wrong-owner/symlink/non-socket node at the expected path and proves the GUI refuses it before connect (`src-tauri/src/daemon/client.rs:147-153`, `src-tauri/src/daemon/server.rs:1136-1175`).

10. **Process-group sibling isolation is already covered and should be preserved.** The standalone contract closes Session A, waits for its shell to terminate, asserts Session B stays alive, and proves Session B still responds (`src-tauri/tests/daemon_persistence_contract.rs:726-806`). The missing close test is the TERM-resistant/escalation case from H-05, not ordinary sibling isolation.

## Section 13 anti-pattern audit

- **UI-only persistence as the solution:** not present. Persisted UI state coexists with a standalone daemon backend.
- **Unconditional terminal respawn on startup:** not present in the current restore path; missing sessions become `exited` (`ui/src/lib/sessionPersistence.ts:334-364`).
- **StrictMode disabled to mask races:** not present; the coordinator explicitly handles cleanup/re-entry (`ui/src/state/workspaceRestore.ts:63-128`).
- **HMR keeps only xterm DOM without backend identity:** not present; backend IDs/epoch/sequence are part of persisted session state (`ui/src/lib/sessionPersistence.ts:316-379`).
- **Background task inside GUI as PTY persistence:** not the production ownership model; daemon constructs the terminal backend (`src-tauri/src/daemon/server.rs:207-225`).
- **`nohup` shell while PTY master remains GUI-owned:** not present.
- **Reuse backend ID without output attach:** not present; terminal host setup attaches through the sequenced scheduler (`ui/src/lib/terminalInstanceFactory.ts:176-187`).
- **Silent direct in-process PTY fallback:** not present in `DaemonClient::connect_or_spawn` (`src-tauri/src/daemon/client.rs:147-194`).

The exported `ensureSessionBackends` / `REBIND_SESSION_BACKEND` pair is therefore **not a current anti-pattern**, because production restore/HMR paths do not call it. It should remain an explicit user-approved replacement-shell mechanism only; wiring it into cold restore would immediately violate the specification (`ui/src/state/workspaceStore.ts:242-281`).

## Regression-risk notes

1. **Highest-risk change surface: attachment event schema.** Fixing H-01 requires changing Rust stream handling, Tauri event payloads, TypeScript decoding, scheduler state, and tests together. Preserve the invariant "history/reset boundary first, then live sequence > boundary" through batching; do not emit replay history as an ordinary live batch without metadata.

2. **Retry changes can regress perceived reliability.** Removing generic retry for `Write`/`Signal` may expose more transient errors. That is preferable to duplicate input, but the UI needs an explicit ambiguous-delivery/error state. If transparent retry is desired, implement protocol-level mutation request IDs rather than guessing.

3. **Strict epoch reconciliation will intentionally mark more sessions lost until the Tauri list contract carries epoch.** Change the Rust list response and UI consumption atomically. Tightening `sessionPersistence.ts` first would make every current live session with a persisted epoch appear lost because `TerminalSessionSummary` currently omits epoch.

4. **Remote protocol-v2 migration affects existing clients.** Add version negotiation to the remote WebSocket protocol or a compatibility window; do not retain silent raw-stream lag behavior as a fallback.

5. **Bounded close escalation must keep process-group isolation.** The existing standalone test proving Session B survives Session A close (`src-tauri/tests/daemon_persistence_contract.rs:726-806`) is a mandatory regression test when adding SIGKILL escalation.

6. **Dynamic CWD authority should stay in the daemon.** Reconnecting the existing GUI-side `process_cwd` helper directly would split backend authority again. Expose live CWD through daemon `DescribeSession` instead.

7. **Last-tab UX and persistence policy must stay separate.** Restoring replacement-tab behavior for an explicit user close is compatible with the spec; reusing the same helper after daemon epoch/session loss is not. Keep the call site tied to explicit close only.

8. **Current dirty-tree concurrency matters for review reproducibility.** `workspaceStore.ts` changed during this review and the final snapshot no longer contains the initially observed replacement-tab branch. Before implementing fixes from this report, establish a single branch/revision baseline and re-run the cited contract tests so fixes are not applied against a moving UI state.

## Recommended fix order

1. Fix **H-01/H-02/H-07** together: preserve runtime replay-gap metadata end-to-end and establish request-level idempotency/at-most-once semantics at the correct boundary.
2. Fix **H-03/M-02/M-07** together: make live-session listing authoritative, epoch-bearing, and fail-closed-to-`failed` rather than fail-as-empty.
3. Fix **H-05** with bounded TERM→KILL→reap and retain the sibling-isolation contract.
4. Fix **H-06/M-03/M-09** to finish lifecycle/security semantics: trusted socket validation, event-driven readiness, dedicated protocol-mismatch error.
5. Migrate remote streaming (**H-04**) to protocol-v2 sequence/replay.
6. Restore authoritative dynamic CWD (**M-04**) and the explicit last-tab UX contract (**M-08**) without introducing auto-respawn.
7. Replace launchd `load/unload` with the specified bootstrap/bootout flow and add the missing real integration/E2E gates.

Until the High findings and the section-11 E2E gaps are closed, the section-12 statement "session persistence is fundamentally solved" should remain **not satisfied**.
