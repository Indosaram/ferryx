## 근본 원인
**여러 앱 인스턴스(dev + release)가 하나의 `~/Library/Application Support/com.ferryx.app/session_state.json`을 last-writer-wins로 공유**하는 구조에서, 빈 상태를 가진 인스턴스의 저장이 좋은 데이터를 통째로 덮어씀.

- 저장은 atomic (tmp → fsync → rename, `src-tauri/src/session/mod.rs`) — 크래시로 인한 파일 파손은 아님. **의도된 hollow 저장**이 문제.
- 복원 로직(`deserializeWorkspaceState`)은 데몬이 죽어도 세션을 `exited`로 표시해 보존하고 레이아웃을 복원함 — 복원 로직 자체는 정상 (1,261 테스트 통과 코드와 동일 빌드).
- 즉 로드 시점(22:11 또는 22:16)에 이미 파일이 hollow였음 → 복원할 데이터가 없었음.
- 백업/복구 수단 전무: Time Machine 미구성, `.tmp` 잔재 없음, APFS 스냅샷은 OS 업데이트 것뿐, WKWebView localStorage 파일 없음.

## 데이터 손실 범위
- 터미널 PTY: 데몬 46901 사망과 함께 소멸 — 내용 복구 불가.
- 탭 레이아웃/세션 목록: hollow 덮어쓰기로 소실 — 복구 불가로 판단.

## 재발 방지 권고 (미구현)
1. **복원 가드**: 부팅 후 해당 워크스페이스 복원이 완료(또는 "빈 상태 확정")되기 전에는 `persistSession` 전체 저장 금지 — hollow 덮어쓰기의 핵심 차단점.
2. **세션 파일 로테이션**: 저장 시 직전 버전을 `session_state.json.bak` 1세대 보존 — 실수 덮어쓰기 되돌림 가능.
3. **인스턴스 격리**: dev(tauri dev)와 release 앱이 같은 daemon.sock + 같은 세션 파일을 공유하지 않도록 분리 (예: dev는 별도 identifier/디렉터리).
4. **데몬 수명 규명**: GUI 종료와 무관하게 살아야 할 데몬이 22:08–22:11 사이 사망 — 크래시 리포트가 없으므로 외부 시그널(사용자 강제 종료 등) 추정, 원인 확인 필요.
