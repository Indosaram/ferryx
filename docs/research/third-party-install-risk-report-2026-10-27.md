# Third-party install risk report (2026-10-27)

Scenario: someone other than the owner installs Ferryx on their own computer (macOS / Windows / Linux)
and connects a remote machine they own (an SSH host, or a headless no-SSH host paired through the relay).

Method: read-only source review at `94c4a3f5` (no builds, no runs). Every finding is labeled
**SOURCE** (established by reading code, cited file:line) or **MEASURED** (taken from a command run
in this session). Severity: **P0** blocks install or use, **P1** breaks a core feature, **P2** friction,
**P3** polish.

Sources: orchestrator checks plus six read-only lanes (install, first run, SSH, paired/relay, docs/privacy, updates/cross-platform). Lane claims marked "Re-read by orchestrator" were confirmed against source this session; everything else is lane-cited SOURCE.

**Bottom line:** 5 P0 dead ends block a third party today - the Windows one-line CLI install, likely the Linux glibc floor, adding any new SSH host, any Alpine/musl remote, and a headless no-SSH host that enrolls but never comes online.

## Prioritized roadmap

1. **Fix the P0 dead ends** (I0, I6, S0, S00, P0x): Windows CLI artifact, glibc floor, SSH host-key trust step, musl helpers, relay mode after headless enroll.
2. **Unblock hardware** (I1, I2, S1): add linux-arm64 and windows-arm64 CLI, and musl helpers. This is the largest group of third parties who cannot install at all.
3. **Updates that actually land and uninstalls that actually remove** (U2, U3, U4, U5): Windows daemon upgrade, staged ui/dist, uninstall hooks on all OSes.
4. **Keep remote sessions alive without systemd** (D1, D2): a fallback supervisor plus clear UI reasons.
5. **Corporate networks** (P1): honor proxies for relay-bound traffic.
6. **Self-hosting** (A1, A3, U1): make relay origin, CSP, mailer and updater feed configurable and documented.
7. **Friction** (I3, I4, S2, A2, F1, I5).
