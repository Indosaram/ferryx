Supported.** `ui/src/lib/browserHistory.ts:15-20,66-98` records only when rememberBrowsingHistory is enabled and clears storage; production callers were found at `ui/src/components/BrowserPane.tsx:131` and settings toggle/clear at `ui/src/components/settings/BrowserSection.tsx:239-242`. Non-Unix uses a loopback TCP listener and daemon.port (`:140-163,1469-1480`), not /tmp UDS; agent socket is Unix-only and best-effort (`:1345-1380,1497-1498`). - **P:27-28 - output ring/reattachment. ## Privacy: remote gateway/network modes

- **P:44 - explicit enable. Correct material omission.** Default mode is Off (`remote/state.rs:53-60`), but a pairing request can auto-enable Relay (`daemon/server.rs:1948-1972`). Say remote access can be enabled by pairing, not only by a network-mode toggle. Previously persisted non-Off config restores on startup (`daemon/server.rs:1500-1505`).
- **P:48 - Off. Correct boundary.** `remote/server.rs:2266-2268` refuses this gateway; `daemon/server.rs:2376-2389` stops it. Off does not mean no remote traffic from the machine: SSH client sessions (`terminal/remote.rs:188-200`), agents, external webviews (`ipc/browser.rs:925-934`), and updater remain independent. The existing update exception alone is insufficient.
- **P:49 - LAN. Supported listener/protocol, not subnet access guarantee.** `remote/state.rs:194-227`; `remote/server.rs:2203-2238,2299-2344`. Resolver may choose public IPv4. Session/control endpoints require authorization; health, static UI, and pair exchange are not paired-only (`remote/server.rs:325-346,2139-2160`). State “paired devices can access protected session endpoints,” not that every gateway route requires pairing.
- **P:50 - Tailscale. Correct guarantee.** Resolver selects any active CGNAT address plus loopback, not authenticated tailscale0 membership (`remote/state.rs:110-112,118-143,229-234`). Binding alone does not establish “restricting connections to your private tailnet”; routing/firewall/Tailscale ACLs are external controls. WireGuard encryption is external Tailscale behavior, not Ferryx TLS or tested deployment evidence.
- **P:51 - Relay TLS. Supported default, not arbitrary custom URL.** `remote/state.rs:20`; `remote/server.rs:2270-2293,2347-2374`; `relay_client.rs:538-549` accepts http/ws as well as https/wss. Qualify TLS to configured secure endpoints; no deployed certificate/relay behavior was inspected.
- **P:53-54 - wildcard/self-host/environment. Supported gateway-only and self-host source; correct override.** `src-tauri/src/bin/relay.rs:21-36,70-110` is a separate relay executable with wildcard HTTP listener, generally requiring external TLS termination. Gateway wildcard and FERRYX_RELAY_URL limitations are mapped at G:310 and G:608. The existence of open-source self-hosting code does not establish a successfully deployed public relay.

## Privacy: what leaves the machine

- **P:58 - HTTPS via proxy. Recommendation/conditional, not guaranteed.** Plain gateway TCP is established at `remote/server.rs:2203-2238`; relay scheme conversion at `relay_client.rs:538-549`. A reverse proxy does not automatically supply TLS: say a **TLS-terminating** proxy. Default public relay URL is HTTPS; live external transport was not tested.
- **P:60-64 - outgoing metadata/context/output. Supported subset; correct names.** `remote/protocol.rs:180-195,232-264` carries workspace/session/tab identifiers, worktree labels, active context, and optional titles. `remote/server.rs:657-767` fills session titles with None or “Terminal”; **process names are not established as a guaranteed metadata field**. There is no paneId in the read context schema; use active session/tab rather than separate pane identifiers unless another real payload is cited. `remote/server.rs:1450-1473,1830-1845` transmits/replays terminal snapshots, with text/grid variants. Terminal output may itself contain process names, but that is different from explicit metadata fields.
- **P:66-71 - Control-only commands. Wrong blanket guarantee.** `remote/server.rs:1477-1528,1850-1920` gates raw keystrokes and interrupt on Control, **but local Resize is not gated by can_control in either text or grid handler** (`:1511-1516,1885-1895`). Worktree create/delete and workspace selection are Control-gated (`:963-969,1090-1096,1136-1142`). State this actual distinction; do not silently treat View as fully read-only. Interrupt implementation writes VINTR byte 0x03 (`terminal/session.rs:210-215`), relying on terminal line discipline rather than guaranteeing a direct SIGINT to all running processes.
- **P:73 - View/no repository browsing. Supported narrower assertions.** Input keystrokes are discarded as above. View can still resize local terminals and revoke itself (`remote/server.rs:1191-1197`). Complete router read at `:2132-2162` exposes no repository-tree browse API; this does not prevent a Control terminal session from invoking shell file commands or mean there is no static file serving.
- **P:75 - push task alerts. Unsupported; remove delivery claim.** `remote/server.rs:2102-2129` only stores/removes subscription payloads. `src-tauri/src/remote/push.rs:16-63` defines a notification struct, JSON formatter, and in-memory registry, with no dispatcher. Symbol search found formatter/list_subscriptions production definitions but no sending caller (remaining uses are tests). Registration is not evidence that endpoints receive agent-name/status/summary alerts. Do not invent a transmitted-data promise from a schema alone.

## Privacy: pairing/tokens/credentials

- **P:79 - “protects every remote connection.” Correct.** Pairing authorizes protected session endpoints; health/UI/exchange are public (`remote/server.rs:325-346,2139-2160`), and plain LAN bearer transport is not encrypted merely because keys exist. SSH/update/webview traffic use their own authentication. Remove the universal phrasing.
- **P:81 - identity first-run/permissions. Correct lazy creation and Unix-only mode**, as at G:417-428 (`remote/auth.rs:75-104,868-910`; `remote/server.rs:332-346,2287-2293`). Existing-file permissions are not repaired by load.
- **P:82-83 - random PIN, expiry, lockout. Supported constants, qualify limitations.** Direct and Relay generators differ in numeric range (`auth.rs:374-393`; `relay_client.rs:131-155`). 60 seconds is maximum creation-relative lifetime; in-memory failure budget is not a durable universal brute-force guarantee (`auth.rs:269-298,446-467`).
- **P:84-85 - bearer generation/store/client. Supported, add persisted PIN disclosure.** `auth.rs:289-298,545-573,735-779`; `ui/src/lib/remoteClient.ts:6-30`. The server stores plaintext bearer-token mapping and expiring PIN/capability records, not just approved device metadata; success may outlive a failed best-effort save. Optional host-specific client token keys also live in localStorage.
- **P:86 - single-use socket tickets. Supported.** `remote/server.rs:254-323` mints with authenticated bearer, binds ticket to target/expiry, removes on redemption, and resolves WebSocket authorization. Direct sockets accept header bearer or ticket, not permanent query bearer. “Can use” is appropriately non-universal; this does not imply encryption of plain HTTP ticket issuance.
- **P:87-88 - expiry/revocation. Supported with lifetime scope.** `auth.rs:648-713,797-805` defines idle/token invalidation and sends revocation watch. `remote/server.rs:1211-1243` subscribes before upgrade and cancels active work when signaled. This is same-manager revocation signaling; avoid claiming an independently edited/deleted auth file synchronously closes every stream. Re-pair replacement also invalidates tokens, as described for G:529-531.
- **P:90-93 - credential paths/memory fallback. Mostly supported, correct “exists.”** `remote/auth.rs:37-73`, `cli.rs:190-218`, `remote/state.rs:374-389,668-684` resolve overrides and platform roots. Windows LOCALAPPDATA then USERPROFILE fallback is supported; non-Windows identity resolver additionally accepts USERPROFILE, unlike normal state/CLI HOME-only resolution. **A missing directory is created** by `auth.rs:868-875`; memory-only gateway state occurs when no base can be **resolved**, not merely when a directory does not exist. CLI returns “Cannot persist pairing state: set FERRYX_DATA_DIR” (`cli.rs:211-212`); identity-dependent exchange/Relay startup can fail rather than fall back to memory (`remote/server.rs:332-346,2287-2293`).
