## 본문

```markdown
안녕하세요. Ferryx를 만들고 있는 개발자입니다.

Claude Code, Codex 같은 CLI 에이전트를 한 저장소에서 여러 개 돌리다 보면 금방 꼬입니다. 한 에이전트가 리팩터링하는 도중에 다른 에이전트가 테스트를 돌리고, 반쯤 고친 파일을 "원래 있던 코드"로 읽어버립니다. 에이전트 문제가 아니라 같은 작업 폴더를 같이 쓰는 구조의 문제였습니다.

`git worktree`로 에이전트마다 작업 폴더를 나누면 해결되지만, 작업마다 worktree 만들고, 터미널 열고, 에이전트 띄우고, 끝나면 정리하는 걸 손으로 하는 게 귀찮았습니다. 그리고 긴 작업을 걸어두고 터미널 창을 실수로 닫으면 에이전트도 같이 죽었습니다. 그래서 이 두 가지를 기본값으로 풀어주는 터미널을 만들었습니다.

### 주요 기능

- **에이전트당 워크트리**: 탭 바에서 에이전트를 띄우면 저장소 안의 격리된 worktree(별도 브랜치)에서 시작합니다. worktree 경로는 저장소 루트 밖으로 나가지 못하게 막아 둡니다.
- **에이전트 상태 표시**: Claude Code, Codex, OpenCode 등을 감지해서 작업 중 / 입력 대기 / 완료 상태를 배지와 알림으로 보여줍니다. "지금 누가 나를 기다리는지"를 탭만 보고 알 수 있게 하는 게 목표입니다.
- **창을 닫아도 세션 유지**: 터미널 세션은 GUI가 아니라 백그라운드의 헤드리스 Rust PTY 데몬이 들고 있습니다. 앱을 끄거나 크래시가 나도 에이전트는 계속 돌고, 다시 열면 시퀀스 번호가 붙은 링 버퍼에서 출력을 이어서 재생합니다.
- **폰에서 확인**: 6자리 PIN / QR로 폰 브라우저를 붙여 터미널 출력을 보고 에이전트에 입력할 수 있습니다.
- **인바운드 SSH 없는 리눅스 서버 페어링**: 헤드리스 서버에 `ferryx-cli`만 설치하면 아웃바운드 릴레이 터널로 연결됩니다. NAT·방화벽 뒤, 공인 IP나 열린 포트가 없는 머신도 붙일 수 있고, 원격 worktree와 터미널이 그 머신에서 직접 돕니다.
- **분할 창·내장 브라우저**: 가로/세로 자유 분할, 탭을 다른 창으로 드래그, 터미널 옆에 브라우저 탭을 띄워 에이전트가 만든 결과를 바로 확인할 수 있습니다.

### 기술 스택

Electron을 쓰지 않았습니다.

- 셸: Tauri v2 (OS 기본 WebKit / WebView2)
- 터미널 파서: libghostty-vt (Ghostty의 VT 코어)
- 렌더링: wgpu 네이티브 차일드 서피스 (오프스크린 렌더 벤치마크 기준 50프레임 p50 3.10ms, Apple M4 Max)
- 세션: Tokio 기반 헤드리스 PTY 데몬 + UDS 프로토콜, 데몬 롤링 업그레이드 시 세션 인계
- 원격: Axum 게이트웨이, 아웃바운드 릴레이
- 프론트: React + TypeScript + Zustand

### 플랫폼과 라이선스

- macOS(유니버설 DMG), Windows(x64 설치본, 아직 코드 서명 전), Linux(AppImage, .deb), 헤드리스 리눅스용 `ferryx-cli`
- 라이선스는 Sustainable Use License(SUL-1.0)입니다. 소스는 공개되어 있고 개인·비상업 용도는 무료이지만, OSI 기준의 오픈소스 라이선스는 아닙니다.
- 일부 OS 연동(launchd, Dock 배지, vibrancy 등)은 아직 macOS가 먼저입니다.
```
